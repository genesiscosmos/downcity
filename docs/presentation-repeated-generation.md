# Presentation 重复生成调查与修复

## 现象与证据

用户提供三个测试 Session，只读检查 canonical 数据库后确认：

- sfr4uuw35naw：OpenUI v2，成功发布一个金融关系模块，约 60 秒后用户停止；该样本不足以单独证明重复循环。
- 4fgn95yeb94n：OpenUI v2，同轮约 152 秒内成功发布七次，反复生成已经包含六种用途的完整演示。
- maxk268zmg2r：旧 v1，首轮成功六次，第二轮成功九次、失败两次；在产品、对比、概念已展示后继续重复，用户要求结束后才收尾。

因此不是单纯前端 loading，也不是 OpenUI 独有问题。用户指定会话没有被修改或重新执行。

## 已确认缺陷

SessionPowerProjection 原本把整个工具输入替换成 `{_downcity_projection, summary}`，导致 action=show 和 args 外壳消失。已在本地复现模型上下文转换。成功回执只包含 published=true，未说明产物摘要与完成后的行为。

这些缺陷使完成反馈不够可靠，但历史记录不足以证明所有模型重复调用都由单一因素造成。

## 修改

- 保留 Power 调用 envelope、action 与非描述参数，仅压缩已发布内容的 args.content / args.spec；未识别形状和未发布调用保持原样。
- 原始描述保留在 canonical Tool Part，不修改事实记录。
- 成功回执增加 summary 和 next_step，明确内容已发布、无需重复生成，同轮完成后可以结束。
- 模型说明明确：界面在 Turn 结束后仍可交互，不必维持执行等待用户；多个不同模块可逐个发布，已完成的集合不重复重做。
- 不添加一次调用即强制停止、全局工具数量限制或猜测性的内容去重。

## 验证与限制

Agent、City、Powers 及依赖构建通过，Desktop 类型检查与生产构建通过，17 项关联检查通过。检查覆盖历史 action 保留、原始参数不变、未发布调用保留、发布回执、多个不同模块、失败修正和原有执行恢复边界。

未执行真实模型付费重放，尚不能据此保证所有模型与提示都自动收尾。需要更新运行中的 Desktop / Agent 后，用新 Session 验证：

1. “用 Presentation 展示一个金融产品关系图。”应发布一次，随后正常结束；控件仍可操作。
2. “分别展示产品、对比、概念三个模块。”允许三个不同产物，或一个覆盖全部要求的模块；不反复重做整组。
3. 人为失败的描述修正成功后，正常收尾；没有错误时不自行反复修复已发布界面。

若复测仍重复，应抓取更新后实际模型输入与输出时序，继续定位，不仅凭 published 回执推断结束。未提交、推送或发布；本次使用 no-bump 构建。
