## 一、病灶：8 套行，5 条文字线

侧栏此前没有「侧栏的行」，只有 8 套各自实现、彼此不知道对方存在的行：

| # | 实现 | 文件 |
| --- | --- | --- |
| 1 | Chat 主体行（Agent / Group） | `layouts/sidebar/ChatSubjectList.tsx` |
| 2 | 会话行 / 新建行 / 「全部对话」行 | `layouts/sidebar/SubjectConversationsPanel.tsx` |
| 3 | 目录树行（根 / 目录 / 文件） | `layouts/sidebar/WorkspaceTree.tsx` |
| 4 | Power 目录条目 | `layouts/sidebar/PowerSidebar.tsx` |
| 5 | 设置条目 | `layouts/sidebar/SettingsSidebarPanel.tsx` |
| 6 | 注入给 Power 的 `SidebarItem` | `features/power/lib/PowerRendererComponents.tsx` |
| 7 | 注入给 Power 的 `SidebarTreeItem` | 同上 |
| 8 | （已删除的）空态与加载态 | 分散在 1 / 3 / 4 三处 |

它们各自决定行高（28 / 32 / 40 / 44 / 48）、圆角（`item` / `control`）、
内边距（4 / 6 / 8 / 10）、行首槽宽（16 / 20 / 24 / 28 / 32）与文字档位（10 / 11 / 12px）。
表现不是「某一处难看」，而是**同一类东西落不到一条线上**：以侧栏左缘起算，
行文字分布在 80 / 84 / 88 / 94 / 96，行首图标分布在 64 / 66 / 70 / 72。

另有三处同源缺陷：

1. **文件图标比同层文件夹图标靠左 28px**。文件夹行有箭头位，文件行没有——而两者在同一层。
2. **cursor 随展开状态变**：折叠态的行写了 `[&_button]:cursor-pointer`，展开成卡片后那段类名不在了。
   根因更靠前：Tailwind v4 的 preflight 不再给 `button` 加 `cursor: pointer`，而应用里只有少数地方手写了它。
3. **面板标题不在行的文字线上**：标题自己再叠了一次 `px-1`，比行盒多出 4px。

## 二、三个变体

```text
agent     [头像 32] 名称 / 描述            ← 身份行：这是谁
default   [字形 32?] 名称                  ← 条目行：这是什么（可不带槽）
settings  [图标 16] 名称                   ← 设置行：比 default 高一档
```

| 变体 | 行首槽 | 行高 | 文字线 | 用在哪 |
| --- | --- | --- | --- | --- |
| `agent` | 32（头像；图标 16 居中） | 44 / 48 | **97** | Chat 主体行、Power 条目、注入的 `SidebarItem` |
| `default` | 无 / 16 / 32 | **32** | **56**（卡片内 57）/ 80 / 100（树，+12×depth） | 会话行、新建行、「全部对话」行、目录树、注入的 `SidebarTreeItem` |
| `settings` | 16 | **40** | **80** | 设置导航 |

**只有这三档，没有第四个出口。** 新增一种行时先回答「它是身份行、条目行，还是设置行」，
而不是「我要多高」。

### 2.1 为什么 `agent` 是 97，`default` 是 56

这两条线回答的是两件事：

- **97 是身份线**：行首是一个 32px 的头像，「这是谁」先于「它叫什么」。Power 条目同理
  （图标居中在那个头像位），因此一个 Power 在目录页与它自己的侧栏里是同一条线。
- **56 是内容线**：行首没有头像，文字直接落在内容起点上，**与面板标题同一条线**——
  侧栏里「这一块叫什么」与「这一条叫什么」本来就该对得上。

差值 41px 不是误差，是「有没有身份物」的结果。

### 2.2 56 是怎么算出来的，以及那 1px

```text
行盒起点 = Rail 40 + 内容内边距 8                    = 48
无边框变体：内容起点 = 48 + 行内边距 8                = 56
agent 变体：内容起点 = 48 + 透明边框 1 + 行内边距 8   = 57
文字线   = 内容起点 + 行首槽 +（有槽时再加 8 的间距）
```

| 行 | 槽 | 文字线 |
| --- | --- | --- |
| `agent` | 32 | 57 + 32 + 8 = **97** |
| `default`（会话行、新建行） | 0 | **56** |
| `default` + 16 | 16 | 56 + 16 + 8 = **80** |
| `default` + 32（目录树） | 32 | 56 + 32 + 8 = **96** |
| `settings` | 16 | **80** |
| 卡片内的 `default` | 0 | 56 + 卡片描边 1 = **57** |

`agent` 那 1px 透明边框**必须存在**：折叠态它画在行上，展开态由卡片接管，两个状态的内容盒
因此重合。少写它，展开那一刻内容会横竖各跳 1px——只在那一下可见，事后极难归因。
其余两个变体不展开成卡片，因此不带边框，也正因如此它们的文字线才是 56 而不是 57。

卡片内的会话行是 57：**卡片自己有 1px 描边**。它没有靠额外内边距去「补回 56」是刻意的——补了就会让卡片内的行与卡片外的行在两个方向上分叉。

#### 2.2.1 卡片下半的 8px 要拆成两层

```text
卡片外：行内边距 8 + 边框 1                    = 9
卡片内：卡片描边 1 + 面板内边距 4 + 行内边距 4  = 9
```

两层相加相等，所以文字仍在同一条线上；而**底色（选中 / hover）缩回卡片内 4、文字离底色左缘也只剩 4**。

这不是审美细节：把面板内边距设成 0、让行自己背完整的 8px，会同时得到两个坏结果——
底色贴到卡片描边上、而内容离底色边缘很远（两层皮）。反过来把 8px 全给面板、行内边距为 0，
则行的底色会宽到碰卡片圆角。这个等式是两侧比例的**唯一**约束。

### 2.3 两种左右内边距：看行首那个东西多大

| 行的行首 | 左右 | 纵向 | 谁在用 |
| --- | --- | --- | --- |
| 32px 的头像 / 带底块图标 | **8** | 4 | `agent` 行（Chat 主体、Power） |
| 16px 的图标 | **8** | 4 | `settings` 行 |
| 24px 的箭头 · 卡片内的文字 | **4** | 4 | 树行、卡片内的会话行 |

依据不是“这一行在哪”，而是**行首元素多大**：32px 的头像需要 8px 才不显拥挤；
24px 的箭头与卡片里的文字只需要 4px。

特别是树行：行 32 高、纵向内边距 4，因此箭头的上下各 4——**左右也必须 4**，
它到四边的距离才相等。左右写 8 会让箭头在一个小方框里看上去偏右。

### 2.4 槽宽只有 0 / 16 / 32（28 是槽里的内容）

- **0**：不放槽。没有图标的行不要放空槽或窄槽——前者把文字往右推，后者往左推，两者都会错开一整档。
- **16**：单个 16px 图标（设置条目）。
- **32**：头像，或两个 16px 字形（目录树的「箭头 + 文件夹/文件」）。

目录树的槽为什么是 32 而不是 16：箭头与图标本来就是两件事（一个说「这里能展开」，
一个说「这是个文件夹」）。文件行左边的**同宽空位**是这轮修掉的缺陷——早先文件行没有箭头位，
它的图标比同层文件夹靠左一整个箭头宽。

### 2.5 行高由槽推出，不另立数值

| 行 | 高 | 依据 |
| --- | --- | --- |
| `agent` 单行 | 44 | 槽 32 + 上下内边距 8 + 边框 2 |
| `agent` 双行 | 48 | 名称 16 + 间距 4 + 描述 15 → 取 4px 网格上不小于它的档 |
| `default` | 32 | 槽 32 就是行高（内边距含在行盒里） |
| `settings` | 40 | 比 `default` 高一档，留出呼吸 |

`settings` 比 `default` 高、但文字线相同：**层级用缩进表达，密度用行高表达**，两者不互相顶替。

### 2.6 文字档位

| 位置 | 档位 |
| --- | --- |
| 行主标签 / 面板标题 | `xs`（12px） |
| 行描述 / 分组标签 | `2xs`（11px） |
| 计数角标 | `3xs`（10px） |

侧栏是唯一允许整片用 `xs`/`2xs` 的业务表面（它是导航，不是阅读面；宽度下限只有 232px），
判据写在 `desktop-type-scale-design.md` §4.1。

### 2.7 圆角、状态与焦点

- **可点行一律 `rounded-item`**（列表项角色），不再混用 `control`。
- 悬停 `hover:bg-interaction-hover`；选中 `bg-interaction-selected hover:bg-interaction-active`。
- 焦点有两种结构，判据是**行底是不是那个可聚焦元素**：
  - 单一控件行（Power 条目、设置条目、会话行、新建行）→ `sidebar_item_class_name`，整行一个环；
  - 复合行（主体行：头像 + 名称 + 菜单；目录树行：箭头 + 标签 + 菜单）→
    `sidebar_item_base_class_name` 提供行底，环由行内各按钮自己声明。
- cursor 统一由 `base.css` 的基础层提供（`button:not(:disabled)` / `[role="button"]:not([aria-disabled="true"])`），
  与展开状态无关；需要保留箭头的场合（菜单项、标签页）用工具类 `cursor-default` 覆盖。

### 2.8 Power 条目的图标底块：唯一的身份差别

```text
Power      [ [ 28 底块 ] 图标 ] ──8── 名称 / 描述         ← agent 变体 + leadingTile
Chat 主体  [ 32 头像            ] ──8── 名称 / 描述         ← agent 变体
```

两者**行高与文字线完全同档**（都是「一个带身份的条目」），差别只有行首那个
28px 的圆角底块（`size-7` + `rounded-item` + `bg-surface-subtle`）。

- 底块**居中在标准的 32 槽内**，因此不引入新的文字线（仍是 97）；
  底块到文字的实际间距是 `2 + 8 = 10`，正是历史实现的 `gap-2.5`。
- 它的作用是把「一个能启用的**能力包**」（Power）与「一个有头像的**身份**」（Chat 主体）
  区分开。删掉它不会报错，只会让 Power 列表看起来像另一份联系人列表。
- 这是从历史实现里找回来的：重构过程中它曾被以“统一成裸图标”的理由删掉，
  而那个理由本身是错的——统一的目标是**同类东西一致**，不是**所有东西一样**。

## 三、各面板如何使用

面板只描述内容，不描述几何。一个常规行就是一次调用：

```tsx
<SidebarItem
  variant="agent"
  active={active}
  leading={<PowerIcon power_id={power.power_id} icon_url={power.icon_url} />}
  title={power.title}
  description={power.description}
  onSelect={() => select_power(power.power_id)}
/>
```

带行内操作入口时**不需要换 API**——传 `menu` 就行，组件自己会从「整行一个按钮」
改成「行底 + 标签按钮 + 操作位」（行里不能嵌按钮）：

```tsx
<SidebarItem variant="default" currentKind="true" active={active} title={title}
  onSelect={select} menu={<SessionActionsMenu … />} />
```

| 面板 | 行 | 标题 / 空态 |
| --- | --- | --- |
| Chat | 主体行 `SidebarRow` + `SidebarRowLabel`（唯一手搭的复合行）+ 卡片内 `SidebarItem` | `SidebarHeader`「Chat」+ 加号菜单；空态 = 图标 + 「暂无聊天主体」+ 建立按钮 |
| Workspace | `SidebarItem variant="default"` + `SidebarTreeLeading` + `indent` | 空态 = 图标 + 「还没有 Workspace」+ 「添加 Workspace」 |
| Powers | `SidebarItem variant="agent"` | 空态与**加载态分开**：读到之前显示「加载中…」，而不是「暂无 Power」 |
| Power 工作区 | 由 Power 用 `ui.Sidebar` / `SidebarItem`（`agent`）/ `SidebarTreeItem`（`default` + 32）组合——**适配层直接渲染同一个 `SidebarItem`** | 缺失插槽 / 错误由宿主渲染 |
| 设置 | `SidebarItem variant="settings"` + 分组标签 | 返回动作是 Header 右侧的图标按钮，与其它面板同位置 |

**会话列表里的三种行都不带行首槽**：原先「新建对话」与「全部对话」各带一个 14px 图标、
会话行没有，于是同一张卡片里的标题落在两个横坐标上。三者身份由位置与文案表达，
图标只是在给同一列制造第二条文字线。

**删掉的三处重复表述**：

- Agent / Group 没有描述时不再顶一句「暂无描述」——新建几个 Agent 之后整列都是这四个字。
- Workspace 空态的标题与按钮不再同名（都是「添加 Workspace」），标题改说状态（「还没有 Workspace」）。
- 设置面板的分组标签不再借用分区名（原来同屏出现两个「账户」和两个「设置」）。

## 四、状态覆盖

| 状态 | 表现 |
| --- | --- |
| 默认 | 行底透明；选中行铺 `interaction-selected` |
| 悬停 | 行底 `interaction-hover`；行内操作入口若默认隐藏，则在此显形 |
| 键盘焦点 | `ring-2 ring-ring/30`，落点见 §2.6 |
| 选中 | `aria-current`（`page` 用于导航项，`true` 用于会话）；底色 + 文字转 `foreground` |
| 加载中 | 面板级 `SidebarEmptyState` + 旋转图标 + 「加载中…」；**不显示空态** |
| 为空 | `SidebarEmptyState`：图标 + 状态陈述 + 可选主按钮，标题与按钮各说一件事 |
| 失败 | Power 工作区显示 `Callout tone="danger"`；行级失败由右侧状态图标表达 |
| 禁用 | `opacity-45` + 不响应 |
| 展开中 | 主体行第三态（浮动 / 嵌入），见 `subjectCard.ts` |

## 五、响应式与折叠

- 侧栏宽度 232–400（默认 280，`shellMotion.ts`）。折叠时 `SidebarFrame` 宽度归零，Rail 仍在；
  Rail 的图标按钮 32×32 与 `agent` 行的行首槽同宽，因此折叠态与展开态的图标列在同一列上。
- 窗口宽度到 760 以下时侧栏自动折叠（`shellResponsive`），此时侧栏规则不再参与布局。
- 行内文字一律 `truncate`；行首槽、状态图标、操作入口都不参与收缩（`shrink-0`），
  被截断的永远是名称与描述。
- 目录树的缩进是**数据**（`depth`），用内联 `paddingLeft` 表达，不拼类名——
  类名里放变量在深度一大时就没有类名可用。缩进只改行盒的位置，不改行高。
- **树的深度上限由宽度决定**：默认 280 下深度 3 的文字线到 132，剩约 130px 给名字。
  更深时名称被截断（`truncate`）而不是溢出，可以接受；再深就该折叠不常看的目录了。

## 六、无障碍

- 每个可聚焦元素都必须有自己的焦点指示（`design_token_drift.test.ts` 逐个 `<button>` 断言）。
- 行底是 `div` 的复合行里，环挂在真正的按钮上；行底不假装可聚焦。
- 展开语义：主体行头像带 `aria-expanded` / `aria-controls`（折叠时不指向不存在的 id）；
  树形行箭头带 `aria-expanded` + 可访问名称。
- 当前项用 `aria-current`，不用颜色单独表达。
- 箭头按钮净宽 14px（要与 16px 图标共用一个 32px 槽），命中区用伪元素向两侧补齐；
  目录行**整行**也能切换，因此鼠标用户不缺目标，箭头主要服务键盘与读屏。

### 7.1 需要目检的清单

这些变化按算术是等价的或有意的，但**必须有一次真实窗口的目检**，测试证明不了：

1. **会话列表从 97 回到 56/57**：确认读起来是「一条会话」而不是「缩进不够」。
   它现在与卡片外 `default` 行同线（差那 1px 描边），但与上面的主体名（97）不对齐——这是有意的。
   另看：选中 / hover 的底色是否缩在卡片内 4px、文字离底色左缘是否只剩 4px（§2.2.1）。
2. **空列表 / 加载中**：副文本（侧栏）字号与颜色应比行文字明显轻一档，
   左缘与它上面那些行的文字对齐（不是对齐到行盒左边）；
   主区域的空态标题可以大一档（那是阅读面），但**侧栏里的空态标题不应比行文字重**。
3. **Skill / Task 的树**：名字应**紧跟箭头**（它们没有图标，不该留图标位）；
   分支与叶子的箭头列仍对齐；选中底色跟着层进内缩。
4. **目录树**：箭头到四边的距离应看上去相等（左右与上下都是 4px）；
   箭头与图标之间、箭头与名字之间都不应出现一段奇怪的空白
   （根节点没有图标，因此它的名字应该紧跟箭头）；
   选中 / hover 的底色应跟子节点一起内缩（而不是从面板左缘铺到节点左边）；
   文件与同级目录应落在同一条线上。看三件事——箭头与图标两列是否整齐；
   子节点的 12px 层进是否读得出层级；深度 2–3 的名称在默认宽度下是否仍能看清。
5. 目录树里点箭头只切换、点名称只打开（根）/ 只切换（目录）、点图标与点名称同效，三者不互相触发。
6. **Power 目录条目**：图标应住在一个 28px 的圆角底块里（不是裸图标），
   行高与文字线与 Chat 主体行一致；确认它读起来是「一个能启用的能力包」而不是「一条记录」。
7. 设置条目 40 高、目录树 32 高：确认「略高」读起来是呼吸而不是错位。
8. 卡片的滚动条两端：卡圆角 12px、面板横向内边距 0，滚动条落在圆角弧内的部分变多。
   悬浮底色会贴到卡片内缘——那是卡片上半（主体行）本来的语言，确认两半是同一条边界。
9. 44 / 48 混排的 Agent 列表节奏。
10. **所有行的两行排版**：标题与描述必须是上下两行（不是并排），且两种行（Power 与 Chat 主体）
   描述到标题的间距一致；描述为空时行高退回单档，不留空位。
11. **所有行的宽度**：每行的底色应铺满侧栏内容区（不是只有字那么长），
   且最右侧不溢出、不被裁掉；树行的右缘与根节点齐平。
12. **Task 的折叠**：展开、收起、再展开都应生效；**收起的必须保持收起**
    （包括当前选中的那一个）；切换选中项时它会自动展开一次，之后不再干预。
13. **Power 工作区（Bot Channel / Skill / Task）**：空态文案与它上面的列表是否同一套字号与弱化程度
   （本轮之前 Chat 的空态是 `text-[11px]/60%`，而列表是 `2xs/muted-foreground`）。

### 8.2 目录树：`default` 行 + 箭头 + 图标

```text
Workspace   [▶ 24]─8─名称                根：有箭头、无图标
  └ 📁 src  [▶ 24]─8─[📁 16]─4─名称      目录：箭头 + 图标
  └ 📄 a.ts [   24]─8─[📄 16]─4─名称      文件：箭头位留同宽空位

每层：外层包裹 marginLeft +12，行盒 w-full
      行盒左缘 12×depth，**右缘始终等于容器右缘**（不溢出）

文字左缘：有图标 100，无图标 80（+12×depth）
```

- **缩进作用在行盒上，不是内容上**：用 `marginLeft` 而不是 `paddingLeft`。
  padding 只把内容往右推，行盒仍从面板左缘开始——于是选中 / hover 的底色会从一个比节点
  更靠左的位置铺开（看起来像“错位的高亮”），而子节点也并没有真的“住在父节点里面”。
- **叶子（文件）也要缩进**：它走单按钮分支，缩进必须在两个结构分支里都传。
  缩进样式在渲染前算一次、两个分支共用（守卫盯着），避免“目录缩进了、文件没缩进”。
- **行必须写 `w-full`**：行的主体要么是 `<button>`，要么是 `flex` 的 `<div>`，
  而**按钮不会像 div 那样填满父级**（`width: auto` 是 shrink-to-fit）——
  不写就缩到只剩内容宽，表现为“这一行的底色只有字那么长”。四个原始实现全都写了它。
- **缩进因此由外层包裹承担**：`w-full` + `marginLeft` 会把行盒推出容器右缘
  （宽度 100% + 左外边距）。包一层之后 `marginLeft` 落在块级包裹上，
  里面的行再 `w-full` 就正好落在右边。这两条是一对，去掉任何一个都会换来另一处错。
- **箭头到图标的间距比普通行内间距窄一档（4 对 8）**：箭头是一个 24px 的**按钮**，
  里面的字形只有 14px，按钮左右各含 5px 内边距。真正看见的空白是 `5 + 间距`：
  写 8 就是 13px（比原来的 9px 宽出一半），写 4 才是原来的手感。
  换句话说：**间距要从看得见的东西算，而不是从盒子算**。
- **图标位没有“占位”这回事**：不传图标就不留位。占位只在“同层里其它节点有图标”时
  才需要（目录与文件并列），而那种情况下调用点本来就该**显式传一个占位节点**。
  判据从“这一行有没有图标”换成“这一层有没有图标”，而后者调用点最清楚。
- **箭头位仍然是自动占位**：叶子没有箭头，但它与分支并列，必须占住箭头列。
  这个占位由组件自己做（不是调用点声明）——因为它总是成立。

每层 12（与重构前一致），根节点不缩进。文字左缘因此是 `100 + 12 × depth`（深度 1 时 112，深度 2 时 124）。
**缩进是树表达层级的唯一手段**：行高不随层数变，字号也不变。

树行**不是第四种行壳**：行高、内边距、圆角、文字档位与会话行完全一致（`default` 变体 + `compact`）。
它只是行首多了两件东西：

- **箭头**：`size-6` 的完整小按钮（`rounded-control` + 悬停底色 + 焦点环）——这是它的**原样式**，
  不要为了塞进某个槽把它压窄；
- **图标**：16px，**住在名字所在的按钮里**，因此点图标也展开/打开（重构前的行为）。

左右 4 + 箭头 24 + 间距 8 + 图标 16 + 间距 4 = 文字线 104（基准是行盒 48，不含面板内容内边距）。

缩进只作用于子节点，步长 12（与重构前一致）；根节点不缩进。
**缩进是树表达层级的唯一手段**：行高不随层数变，字号也不变。

箭头位与图标位都必须有占位：没有箭头就不占位，叶子行的图标会比同级目录的图标左移一整个箭头宽；
没有图标就不占位，根节点的名字会在图标列上左移。

### 8.3 只有一条渲染路径

```tsx
<div 行底>              {/* SidebarRow：底色 + 行高 + 圆角 */}
  [行首]                 {/* 箭头 / 图标 / 头像 / 底块 */}
  <button 标签区>          {/* SidebarRowLabel：标题 + 描述 */}
  [尾随]
  [操作位]                {/* 有 menu 才渲染 */}
</div>
```

行底永远是 `<div>`，可点的是里面那个标签按钮——**不因“有没有菜单”而变**。

早先有两条分支（「整行一个按钮」与「行底 + 标签 + 操作位」），各自渲染一遍同样的东西。
代价立刻显现，而且是两次：

| 分支 | 错在哪 | 界面表现 |
| --- | --- | --- |
| 整行一个按钮 | 丢了 `w-full`（按钮不填满父级） | 底色只有字那么长 |
| 行底 + 标签 | 标题与描述被摆成并排（父级 `flex items-center`） | 两个内容挤在一行 |

两次都是“同一段排版写了两遍，其中一遍错了”。现在只有一条路径，这两个错误在结构上
就不可能再发生。代价是多一层 `<div>`——比“同一种行在两处长得不一样”便宜得多。

**行首形状是一个枚举**（`icon` / `avatar` / `tile`），不是一个布尔值组。
早先的 `leadingWidth` / `leadingAvatar` / `leadingTile` 能表达出「既是头像又是底块」
这种不存在的组合，调用点还得知道哪个优先。

### 8.4 文字区：标题与描述是**两行**，且只有一个来源

```text
[行首]  标题
        描述            ← 第二行，mt-1（4）
```

踩过的坑：单按钮分支把文字包在 `flex items-center` 里，而标题与描述是两个块级元素——
它们因此变成**并排的 flex 项**，表现为“两个内容挤在一行”。Power 条目走的正是那条分支。

两个结论：

1. **要两行，只能让文字区自己是一列**：外层负责占宽度与图标对齐，不负责文字方向；
2. **这段排版只有一个来源**（`SidebarRowTitleArea`）：各写一份迟早会分叉，
   而分叉的表现就是“同一种行在两个地方长得不一样”。

描述与标题的间距 `mt-1`（4）不是随手取的：`agent` 双行的行高正是用它算的
（名称 16 + 4 + 描述 15 = 35 → 48），改这里必须同步行高。

### 8.5 卡片内的行：`compact`

```tsx
<SidebarItem variant="default" compact title={conversation.title} onSelect={…} menu={…} />
```

`compact` 的判据与上面那张表一致：两侧 8px 让给行盒之后，剩下的空间容不下再抩 8px。
树行**不用传**——它的 `tree` 已经自带这个属性。

### 8.6 几何出口（只有行实现可以碰）

`sidebarRow.ts`：`SIDEBAR_ROW_ORIGIN`(48)、`SIDEBAR_ITEM_CONTENT_INSET`(56)、
`SIDEBAR_TEXT_INSETS`(97/56/80)、`SIDEBAR_TREE_TEXT_INSET`(96)、`SIDEBAR_PANEL_TEXT_INSET`(57)
都是**算出来的**；类名常量供组件内部使用。

### 8.7 分层的硬边界

```
面板（PowerSidebar / SettingsSidebarPanel / SubjectConversationsPanel / WorkspaceTree）
  │  只组装组件，不得 import sidebarRow.ts
  ▼
组件（SidebarItem / SidebarRow / SidebarDisclosure / SidebarLeading / …）
```

## 九、Power / Bot Channel 侧栏：另一个包，另一套令牌

### 9.1 病灶：收敛没有跨包

`design_token_drift.test.ts` 只扫 `app/desktop/src/renderer`。
**Power Renderer 在另一个包里**，于是 desktop 那套收敛在 Power 里完全不存在：

| 位置 | 写法 | 为什么是问题 |
| --- | --- | --- |
| Chat / Task / Skill 侧栏的空态 | `text-[10px]` / `text-[11px]` | 固定 px 不跟随界面缩放，且不在语义档位上 |
| 同上 | `text-muted-foreground/55` / `/60` | 次要文字只有一档，叠透明度不可收敛 |
| 同上 | `pl-9` / `pl-2` / `px-2` | 三个值“看起来都对”，因为它们分别对齐了不同的东西 |
| Chat 二维码容器 | `rounded-lg` | 命名档位而不是角色名 |
| Chat 二维码说明 | `text-[0.8125rem]` / `text-[0.6875rem]` | 任意 rem 值，绕过档位收敛 |
| Task / Skill 空态 | `min-h-8` + 手搭 `<div>` | 第二套行高 |

后果不是“不好看”，而是**同一个侧栏里出现两套字号与两套弱化程度**：
Chat 的 Bot Account 列表和它自己的空态说的不是同一种视觉语言。

### 9.1.1 空态字号按**插入位置**分档

同一个 `EmptyState` 组件同时服务于侧栏与主区域，而两处的合适字号不同：

| 表面 | 标题 | 说明 |
| --- | --- | --- |
| 侧栏（232–400px） | `text-xs`（12px） | 与它旁边的行文字同档；写 15px 会比列表本身还重，像一条“内容” |
| 主区域 | `text-base`（15px） | 那是阅读面，空态可以当一个小标题 |

它以前写死 `text-base`，于是 Power 侧栏的空态比它上面那些行大一整档。
判据是**组件看得到自己在哪个表面**（`surface`），不是一刀切。

桌面自己的侧栏空态（`SidebarEmptyState`）同样是 `text-xs`——两处必须同档。

### 9.2 两个新接口

**`SidebarSubText`（宿主注入）**——行外副文本：

```tsx
<SidebarSubText indent={1}>暂无执行记录</SidebarSubText>
```

它把三件事收进宿主：左缘对齐到同级行的文字线（带 `indent` 时按层进）、字号 `2xs`、弱化色 `muted-foreground`。
Power 不再自己拼 `<div>`——那是上面那三个内边距值的来源。

**`SidebarTreeItem` 的数字 `trailing` 由适配层包成计数胶囊**：

```tsx
trailing={workspace.skills.length}   // 只交出一个数
```

圆角、底色、字号都来自宿主。Power 自己拼一个圆角方块就会与行分叉（本轮之前就是这么做的）。

### 9.3 新增守卫：`packages/implementations/powers/scripts/power-renderer-tokens.test.mjs`
