# Custom Plugin

A CLI Plugin is a prebuilt static artifact. Its repository uses a JSON manifest to describe the entry and configuration contract. After installation, City adds the Plugin to the shared Catalog and stores enablement and configuration separately for each Agent.

## Artifact structure

```text
example-plugin/
├── downcity.plugin.json
└── dist/
    ├── index.js
    ├── config.schema.json
    └── resource.schema.json
```

`downcity.plugin.json`:

```json
{
  "manifest_version": 1,
  "name": "example",
  "version": "1.0.0",
  "entry": "dist/index.js",
  "title": "Example",
  "description": "An example Plugin",
  "config": {
    "schema": "dist/config.schema.json",
    "defaults": {
      "endpoint": "https://example.com"
    }
  },
  "resources": {
    "schema": "dist/resource.schema.json"
  }
}
```

The manifest must be static JSON. `entry`, `config.schema`, and `resources.schema` are paths relative to the repository root and cannot escape that root or point through symbolic links. Plugins without Resources omit `resources`.

## Configuration contract

The configuration contract uses JSON Schema 2020-12. You can define it with Zod in source code and emit JSON Schema during the build:

```ts
import { z } from "zod";

export const config_schema = z.object({
  endpoint: z.url(),
}).strict();

const json_schema = z.toJSONSchema(config_schema, {
  target: "draft-2020-12",
});
```

Your build script must write `json_schema` to `dist/config.schema.json`. City uses Ajv to validate the schema and defaults during installation, then validates every Agent Binding against the same schema. Zod is not the runtime protocol and does not belong in the manifest.

## Resource Schema and Resolver

A Resource Schema describes one complete Item and requires `id`, `type`, and `name`. `id` must be `readOnly`; the Resolver writes other top-level `readOnly` fields, while users enter `writeOnly` fields securely and the CLI redacts them from output.

```json
{
  "title": "API Account",
  "type": "object",
  "required": ["id", "type", "name", "api_key"],
  "properties": {
    "id": { "type": "string", "readOnly": true },
    "type": { "type": "string", "const": "api" },
    "name": { "type": "string", "readOnly": true },
    "api_key": { "type": "string", "writeOnly": true }
  },
  "additionalProperties": false
}
```

The Resolver returns the complete dynamic-field projection. It cannot modify `id`, `type`, or user-owned fields:

```ts
resolve_resource({ resource }) {
  return { name: inspect_name(String(resource.api_key)) };
}
```

## Runtime Factory

The entry must export `plugin_factory`; a default export is also accepted. The Factory receives the validated Agent `config` and complete `resources` resolved from Resource IDs:

```ts
import type { JsonObject, Plugin } from "@downcity/agent";

export const plugin_factory = {
  async resolve_resource({ resource }: { resource: JsonObject }) {
    return { name: await resolve_name(resource) };
  },

  create({ config, resources }: {
    config: JsonObject;
    resources: JsonObject[];
  }): Plugin {
    return {
      name: "example",
      title: "Example",
      description: `${String(config.endpoint)} · ${resources.length} resources`,
      actions: {},
    };
  },
};
```

The returned `name` must match the manifest `name`. `dist/index.js` must be self-contained ESM: bundle runtime dependencies into the artifact and use `@downcity/agent` only as a type-only build dependency.

## Install and configure

```bash
# Local directory
city plugin install ./example-plugin

# Git URL with an optional branch or tag
city plugin install https://github.com/acme/example-plugin.git#v1.0.0

# GitHub shorthand
city plugin install github:acme/example-plugin#main

city plugin update example
city plugin resource create example --interactive
city plugin resource list example
city plugin config example my-agent --interactive
city plugin config example my-agent --resources '["api-a1b2c3"]'
city plugin enable example my-agent
```

You can also open `city plugin` to install, update, select an Agent, configure, enable, or disable Plugins interactively. Restart a running Agent after a configuration change to assemble a new Runtime.

## Trust boundary

Installation reads only the manifest, JSON Schema, and static files. It does not run `npm install`, build scripts, lifecycle scripts, or the Plugin entry. City records the resolved Git commit for Git sources and a SHA-256 digest of the complete artifact.

The Plugin entry executes while creating, editing, or refreshing Resources and when an Agent starts, so install only trusted sources. Static installation checks are not a substitute for reviewing third-party runtime code.
