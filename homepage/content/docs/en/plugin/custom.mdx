# Custom Plugin

A third-party directory defines exactly one Plugin. The Plugin's globally unique ID is also its final directory name, Agent reference key, and runtime Registry key.

## Directory structure

```text
github-plugin/
├── plugin.json
├── package.json
└── dist/index.js
```

The ESM entry exports the Plugin constructor as the named `plugin` export:

```ts
export const plugin = GithubPlugin;
```

## Plugin constructor

```ts
import type { Plugin, PluginActions } from "@downcity/agent";
import { z } from "zod";

const github_config_type = z.object({
  api_url: z.url().default("https://api.github.com").meta({ title: "API URL" }),
  token: z.string().min(1).meta({ title: "Token", writeOnly: true }),
}).strict();

export type GithubPluginConfig = z.infer<typeof github_config_type>;

export class GithubPlugin implements Plugin {
  static readonly type = { config: github_config_type };

  readonly name = "github";
  readonly title = "GitHub";
  readonly description = "GitHub integration";
  readonly actions: PluginActions;

  constructor({ config }: { config: GithubPluginConfig }) {
    this.actions = {};
  }
}

export const plugin = GithubPlugin;
```

The instance `name`, `plugin.json` `id`, directory name, and Agent reference must match. The constructor does not repeat a `static manifest`; `type.config` is the only source of truth for profile types, defaults, and validation. Builtin and third-party Plugins resolve to the same runtime registration protocol:

```ts
new PluginConstructor({ config: selected_profile });
```

The Loader first runs `PluginConstructor.type.config.parse(raw_profile)` and then passes the complete parsed configuration to the constructor. Accounts, tokens, endpoints, and other structures belong directly to the Zod type. There is no framework-level Binding, Resource, Resolver, or Installation domain.

## Plugin definition

The source directory contains one `plugin.json`:

```json
{
  "schema_version": 1,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub integration",
  "entry": "dist/index.js"
}
```

Plugin authors do not write JSON Schema. The installer derives an input JSON Schema and available defaults from `type.config`, then writes that snapshot together with `source`, `revision`, `integrity`, and timestamps into the installed `plugin.json`. It does not generate a second Manifest.

The `entry` must be a self-contained ESM artifact. Bundle runtime Zod usage into `dist/index.js`; the installer does not install dependencies.

The installed layout is deterministic:

```text
~/.downcity/plugins/github/
├── plugin.json
├── config.toml
├── package.json
└── dist/index.js
```

`config.toml` contains only named plaintext profile values and uses file mode `0600`. CLI and Desktop build forms from the Zod-generated Schema and redact fields marked with `.meta({ writeOnly: true })`. Zod `.default()` fills fields omitted from TOML.

```toml
schema_version = 1

[profiles.production]
api_url = "https://api.github.com"
token = "plain-local-token"
```

An explicitly selected missing profile is an error. Without an explicit selection, Downcity reads the `default` profile and passes `{}` to Zod when that profile does not exist.

## Install and configure

```bash
city plugin install ./github-plugin
city plugin config github production --interactive
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

Updates atomically replace the complete Plugin directory while preserving `config.toml`. The CLI rejects an update when saved profiles fail the new Schema, and rejects profile or Plugin removal while an Agent still references it.

Installation does not run `npm install`, build scripts, or Plugin lifecycle hooks. The installer imports the entry to validate the `plugin` constructor, so module-level code executes, but the constructor is not called. Static code and resources receive a SHA-256 digest; install only trusted sources.
