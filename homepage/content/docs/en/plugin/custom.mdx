# Custom Plugin

One directory defines one Plugin. The Plugin ID is its install directory, Agent reference key, and runtime identity. There is no separate Extension identity.

## Three optional entries

```text
Plugin
├── agent      creates Agent runtime instances
├── main       provides host management logic and actions
└── renderer   provides the single Mainview
```

Each entry is optional, but at least one is required. A Plugin may provide only Agent capabilities, only a Mainview, or a complete runtime and configuration experience.

Recommended development layout:

```text
github-plugin/
├── plugin.json
├── package.json
├── README.md
├── assets/icon.svg
├── src/
│   ├── plugin.ts
│   ├── agent.ts
│   ├── main.ts
│   └── renderer.tsx
└── dist/
    ├── agent.js
    ├── main.js
    └── renderer.js
```

All three entries use ESM. `agent.js` and `main.js` must be self-contained. `renderer.js` is a single-file browser bundle that default-exports the only React Mainview. Downcity does not install dependencies or run build scripts.

## Direct SDK usage

The Plugin class constructor belongs entirely to the author. SDK users can create an instance directly without `plugin.json` or a Profile:

```ts
const github_plugin = new GithubPlugin({
  api_url: "https://api.github.com",
  token: process.env.GITHUB_TOKEN ?? "",
});

const agent = new Agent({
  id: "coding-pro",
  model,
  plugins: [github_plugin],
});
```

The following entry protocol is only needed when CLI or Desktop must install, discover, and manage the Plugin.

## Plugin definition

```json
{
  "schema_version": 1,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub integration",
  "icon": "./assets/icon.svg",
  "agent": "./dist/agent.js",
  "main": "./dist/main.js",
  "renderer": "./dist/renderer.js"
}
```

`package.json` must declare `"type": "module"`. `README.md` is required user documentation and is safely rendered in the Desktop Plugin Overview; describe the Plugin's purpose, configuration, and required credentials there. The icon may be an HTTP(S) URL or a file relative to the Plugin root and is used in Plugin navigation and the Overview.

## Agent entry

`agent` default-exports a factory. The host calls it for each Agent with a snapshot of the selected Profile:

```ts
import type { AgentPluginModule } from "@downcity/agent";
import { GithubPlugin } from "./plugin.js";

const create_agent_plugin: AgentPluginModule<GithubPlugin>["default"] = (context) => {
  return new GithubPlugin(context.profile as unknown as GithubPluginConfig);
};

export default create_agent_plugin;
```

Every call must return a new Plugin instance whose `name` equals `plugin.json.id`. The factory is a host assembly adapter, not an installer or a replacement for Agent Plugin `start/stop` lifecycle hooks.

## Main entry

`main` default-exports a lifecycle object. It registers actions for the Mainview and owns configuration validation and credential protection:

```ts
import { define_plugin_main } from "@downcity/plugin";

export default define_plugin_main({
  activate({ plugin }) {
    plugin.action({
      id: "profile.read",
      run: async (_input, context) => {
        const config = await context.config.get();
        return { api_url: config.api_url, token_configured: Boolean(config.token) };
      },
    });

    plugin.action({
      id: "profile.save",
      run: async (input, context) => {
        const current = await context.config.get();
        const config = validate_and_restore_secret(input, current);
        await context.config.set(config);
        return { saved: true };
      },
    });
  },
});
```

One main is activated once per host. The current Profile is injected only for an action call, so one main can safely serve multiple Profiles. Do not cache a Profile in global state.

## Mainview entry

Mainview is the Plugin's only frontend slot. The Renderer default-exports a React component and composes host-provided UI Components:

```tsx
import { useEffect, useState } from "react";
import { define_plugin_renderer } from "@downcity/plugin/react";

export default define_plugin_renderer(function GithubMainview({ plugin, ui }) {
  const { Button, Group, Input, LoadingState, Page, Row, Toolbar } = ui.components;
  const [profile, set_profile] = useState<{ api_url: string }>();

  useEffect(() => {
    void plugin.invoke<{ api_url: string }>("profile.read").then(set_profile);
  }, [plugin]);

  if (!profile) return <LoadingState label="Reading Profile…" />;
  return <Page>
    <Toolbar title="GitHub" actions={<Button variant="primary" on_click={() => void plugin.invoke("profile.save", profile).then(() => ui.toast({ type: "success", message: "Saved" }))}>Save</Button>} />
    <Group>
      <Row label="API URL" trailing={<Input value={profile.api_url} on_value_change={(api_url) => set_profile({ ...profile, api_url })} />} />
    </Group>
  </Page>;
});
```

The Renderer bundle must leave `react` and `react/jsx-runtime` as host externals mapped to `downcity-plugin://runtime/react` and `downcity-plugin://runtime/react/jsx-runtime`. Bundle other frontend dependencies into the single `renderer.js` file.

Desktop loads the Renderer in its host React tree and binds the current Plugin/Profile. Props expose only `plugin.invoke()`, `ui.components`, Toast, and Confirm—never the Profile ID or Desktop controller. Renderer is trusted local UI code, so install only trusted sources. External URLs, clipboard writes, file reveals, and business persistence should go through explicit main actions.

## Profile interaction

```text
Open Plugin
→ create or select Profile
→ configure it in Mainview
→ enable Plugin for an Agent and select Profile
```

A Profile is only host-provided configuration space. The host creates, selects, removes, and persists it, but does not interpret fields or generate a form from JSON Schema. Structure, validation, defaults, and Secret behavior belong to the Plugin.

Configuration is stored under `~/.downcity/plugins/<plugin_id>/config.toml` with directory mode `0700` and file mode `0600`. The current store uses TOML, so values must be a TOML-compatible JSON object. `agent.json` stores only the Profile reference, and multiple Agents may explicitly share one Profile.

## Install

```bash
city plugin install ./github-plugin
# Create and configure production on the GitHub Plugin page in Desktop
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

The installer copies only `plugin.json`, `package.json`, `README.md`, declared entries, and an optional local icon. It never runs dependency installation, build scripts, or any entry. Entries cannot escape the Plugin root or use symlinks. Installed artifacts receive a SHA-256 integrity digest. Install only trusted sources.
