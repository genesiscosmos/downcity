# Custom Plugin

A third-party directory defines exactly one Plugin. The Plugin's globally unique ID is also its final directory name, Agent reference key, and runtime Registry key.

## Directory structure

```text
github-plugin/
├── plugin.json
├── package.json
└── dist/index.js
```

The ESM entry exports the Plugin constructor as the named `plugin` export:

```ts
export const plugin = GithubPlugin;
```

## Plugin constructor

```ts
import type { Plugin, PluginActions } from "@downcity/agent";

export interface GithubPluginConfig {
  api_url: string;
  token: string;
}

export class GithubPlugin implements Plugin {
  readonly name = "github";
  readonly title = "GitHub";
  readonly description = "GitHub integration";
  readonly actions: PluginActions;

  constructor({ config }: { config: GithubPluginConfig }) {
    this.actions = {};
  }
}

export const plugin = GithubPlugin;
```

The instance `name`, `plugin.json` `id`, directory name, and Agent reference must match. The constructor does not repeat a Manifest or runtime Schema. TypeScript types serve Plugin code, while `plugin.json.config.schema` defines the runtime profile protocol:

```ts
new PluginConstructor({ config: selected_profile });
```

The Loader validates the profile against JSON Schema, then passes the complete configuration to the constructor. Accounts, tokens, endpoints, and other structures belong directly to the Plugin profile. There is no framework-level Binding, Resource, Resolver, or Installation domain.

## Plugin definition

The source directory contains one `plugin.json`:

```json
{
  "schema_version": 1,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub integration",
  "entry": "dist/index.js",
  "config": {
    "schema": {
      "type": "object",
      "properties": {
        "api_url": { "type": "string", "format": "uri" },
        "token": { "type": "string", "minLength": 1, "writeOnly": true }
      },
      "required": ["api_url", "token"],
      "additionalProperties": false
    }
  }
}
```

Plugin authors declare the complete JSON Schema and optional `defaults` directly in `plugin.json`. The installer validates the Schema, defaults, and saved profiles, then writes source, integrity, and timestamps into the same installed file. It does not generate a second Manifest or Schema snapshot.

The `entry` must be a self-contained ESM artifact. The installer does not install dependencies or import the Plugin entry.

The installed layout is deterministic:

```text
~/.downcity/plugins/github/
├── plugin.json
├── config.toml
├── package.json
└── dist/index.js
```

`config.toml` contains only named plaintext profile values and uses file mode `0600`. CLI and Desktop build forms from the `plugin.json` Schema and redact fields marked `writeOnly`.

```toml
schema_version = 1

[profiles.production]
api_url = "https://api.github.com"
token = "plain-local-token"
```

An explicitly selected missing profile is an error. Without an explicit selection, Downcity reads the `default` profile, falls back to `plugin.json.config.defaults` or an empty object, then validates it against the Schema.

## Install and configure

```bash
city plugin install ./github-plugin
city plugin config github production --interactive
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

Updates atomically replace the complete Plugin directory while preserving `config.toml`. The CLI rejects an update when saved profiles fail the new Schema, and rejects profile or Plugin removal while an Agent still references it.

Installation does not run `npm install`, build scripts, Plugin lifecycle hooks, or the entry module. The constructor export and instance ID are validated when an Agent actually loads the Plugin. Static code and resources receive a SHA-256 digest; install only trusted sources.
