# Custom Plugin

A third-party artifact defines exactly one Plugin. The Plugin's globally unique ID is also its final directory name, Agent reference key, and runtime Registry key.

## Artifact structure

```text
github-plugin/
├── downcity.plugin.json
└── dist/index.js
```

The ESM entry exports one named constructor:

```ts
export const plugin = GithubPlugin;
```

## Plugin constructor

```ts
import type { JsonObject } from "@downcity/agent";

export class GithubPlugin {
  static readonly manifest = {
    name: "github",
    version: "1.0.0",
    title: "GitHub",
    description: "GitHub integration",
    config: {
      schema: GITHUB_PROFILE_JSON_SCHEMA,
      defaults: { api_url: "https://api.github.com" },
    },
  };

  readonly name = "github";
  readonly actions = {};

  constructor({ config }: { config: JsonObject }) {
    // config is the complete profile selected by the Agent.
  }
}
```

The instance `name`, static `manifest.name`, installation Manifest `id`, and directory name must match. Runtime construction is always:

```ts
new GithubPlugin({ config: selected_profile });
```

Accounts, tokens, endpoints, and other structures belong directly to the profile Schema. There is no framework-level Binding, Resource, Resolver, or Installation domain.

## Static manifest

Installation reads a v4 static file without executing third-party code:

```json
{
  "manifest_version": 4,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub integration",
  "entry": "dist/index.js",
  "config": {
    "schema": {
      "type": "object",
      "properties": {
        "api_url": { "type": "string", "format": "uri" },
        "token": { "type": "string", "writeOnly": true }
      },
      "additionalProperties": false
    },
    "defaults": { "api_url": "https://api.github.com" }
  }
}
```

The installed layout is deterministic:

```text
~/.downcity/plugins/github/
├── plugin.json
├── config.toml
└── artifact/
```

`config.toml` contains named plaintext profiles and uses file mode `0600`. CLI and Desktop redact Schema fields marked `writeOnly` when displaying configuration.

## Install and configure

```bash
city plugin install ./github-plugin
city plugin config github production --interactive
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

Updates replace only `plugin.json` and `artifact/`, preserving `config.toml`. The CLI rejects an update when saved profiles fail the new Schema, and rejects profile or Plugin removal while an Agent still references it.

Installation never runs `npm install`, build scripts, lifecycle scripts, or the Plugin entry. It records the resolved Git commit and SHA-256 artifact digest. The entry executes when an Agent loads the Plugin, so install only trusted sources.
