# Task Plugin

The Task plugin lets your Agent schedule and run background jobs. It is useful for periodic data fetching, report generation, or any work that should happen outside the normal request-response flow.

## What it does

- Schedules tasks to run at specific times or intervals
- Persists task state across Agent restarts
- Handles retries and failure recovery
- Provides a task queue for deferred work

## Desktop workspace

Task does not declare Config, so it needs no Profile. It remains visible in the Plugins Catalog for its documentation and also contributes a top-level navigation entry. Opening the Task entry shows its Plugin Sidebar for selecting an Agent and Task, while the Mainview selects a Workspace and displays the Task list or details. It reads the selected Agent's Task runtime directly instead of storing a second copy. The current Desktop workspace is read-only; create, edit, run, and delete operations still use Task actions or the CLI.

## Defining a task

Tasks are defined in the project and registered with the Task plugin at startup. They can be triggered by:

- Cron expressions
- One-shot scheduling
- Event-driven triggers

## Use cases

- Daily data sync
- Periodic report generation
- Background file processing
- Scheduled notifications

Each run creates an independent task Session while reusing the host Agent's capabilities. If the task Agent needs to send a chat message, it calls the Chat plugin from the task Session. The completed result is appended as an assistant message to the associated Session.
