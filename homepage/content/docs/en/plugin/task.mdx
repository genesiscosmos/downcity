# Task Plugin

The Task plugin lets your Agent schedule and run background jobs. It is useful for periodic data fetching, report generation, or any work that should happen outside the normal request-response flow.

## What it does

- Schedules tasks to run at specific times or intervals
- Persists task state across Agent restarts
- Handles retries and failure recovery
- Provides a task queue for deferred work

## Desktop workspace

Task does not declare Config, so it needs no Profile. It remains visible in the Plugins Catalog for its documentation and also contributes a top-level navigation entry. Its Plugin Sidebar groups every Task as `Agent → Task`. Selecting a Task opens an execution-history sidebar inside the Mainview and defaults to the latest run. The content area shows final output, status, trigger, duration, validation, and failure details, and can return to the Task definition.

Desktop can create, edit, enable, pause, run, and delete Tasks directly. Workspace is not a page filter: each Task binds exactly one execution Workspace, used by both manual and scheduled runs. The history sidebar is independently scrollable, collapsible, and resizable. The workspace uses the selected Agent's Task runtime and existing run artifacts directly instead of storing a second copy.

## Defining a task

Tasks are defined in the project and registered with the Task plugin at startup. They can be triggered by:

- Cron expressions
- One-shot scheduling
- Event-driven triggers

## Use cases

- Daily data sync
- Periodic report generation
- Background file processing
- Scheduled notifications

Each run creates an independent task Session while reusing the host Agent's capabilities. `session_id` is an optional result-delivery setting: when present, the completed result is appended to that Session; otherwise the result remains available in Task run history. If the task Agent needs to send a chat message, it calls the Chat plugin from the task Session.
