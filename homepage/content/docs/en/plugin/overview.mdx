# Plugin

A **Plugin** is Downcity's single extension product unit. City provides and owns it, projecting runtime capabilities into Agent/Session scopes while also supporting host management logic, a Sidebar + Mainview workspace, and Config.

```text
Plugin
├── main       optional: City instances, lifecycle, management logic, and actions
└── renderer   optional: Sidebar + Mainview and/or Config
```

## What a plugin does

- Exposes tools the Agent can call during execution
- Hooks into City Plugin lifecycle (`initialize`, `dispose`)
- Manages its own state, connections, and background tasks
- Provides a Profile-independent Sidebar + Mainview workspace and edits configuration in a separate Config on its Catalog detail page
- Runs inside the City process boundary, not as a separate service

A Profile is host-provided named configuration for a Plugin and is unrelated to the functional
workspace. Each Plugin ID maps to one instance inside a City. Configuration is projected into
`PluginContext.config` for the current Agent; Agent owns neither the instance nor lifecycle.

## Built-in plugins

Downcity ships several built-in plugins that cover common agent needs:

- **Chat** — connects messaging channels (Telegram, Feishu, QQ, etc.)
- **Task** — schedules and runs background tasks
- **Memory** — persists conversation history and context
- **Shell** — executes local commands in a sandboxed environment
- **Schedule** — cron-style job scheduling
- **Web** — browses the web and extracts content
- **Skill** — composes reusable tool chains

## Writing a plugin

In the SDK, provide a Plugin instance directly without using the install protocol:

```ts
const city = new City({ plugins: [github_plugin], workspaces: [workspace] });
city.agents.add(agent);
```

Add a `plugin.json` with a unified `main` and optional `renderer` entry only when the Plugin must be installed and managed by CLI or Desktop.
