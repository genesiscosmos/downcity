# Plugin

A **Plugin** is Downcity's single extension product unit. It may provide Agent runtime capabilities, host-side management logic, a Sidebar + Mainview workspace, and Config without introducing a separate Extension identity.

```text
Plugin
├── agent      optional: Agent runtime capability
├── main       optional: management logic and actions
└── renderer   optional: Sidebar + Mainview and/or Config
```

## What a plugin does

- Exposes tools the Agent can call during execution
- Hooks into the Agent lifecycle (start, stop, session events)
- Manages its own state, connections, and background tasks
- Provides a Profile-independent Sidebar + Mainview workspace and edits configuration in a separate Config on its Catalog detail page
- Runs inside the Agent process boundary, not as a separate service

A Profile is only host-provided configuration space for a Plugin that declares Config; it is unrelated to the functional workspace. The Plugins Sidebar always shows the complete Catalog, and every Plugin opens a detail page with its description, README, and optional Config. Functional Plugins also appear on the top-level navigation rail; selecting one replaces the Sidebar with its own navigation and renders its Mainview. A Plugin without Config does not need a Profile. Business configuration never lives in `agent.json`.

## Built-in plugins

Downcity ships several built-in plugins that cover common agent needs:

- **Chat** — connects messaging channels (Telegram, Feishu, QQ, etc.)
- **Task** — schedules and runs background tasks
- **Memory** — persists conversation history and context
- **Shell** — executes local commands in a sandboxed environment
- **Schedule** — cron-style job scheduling
- **Web** — browses the web and extracts content
- **Skill** — composes reusable tool chains

## Writing a plugin

In the SDK, a Plugin remains a regular TypeScript instance and can be passed directly to an Agent without the install protocol:

```ts
const agent = new Agent({
  id: "coding-pro",
  model,
  plugins: [new GithubPlugin({ token })],
});
```

Add a `plugin.json` with optional `agent`, `main`, and `renderer` entries only when the Plugin must be installed and managed by CLI or Desktop.
