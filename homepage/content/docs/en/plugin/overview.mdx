# Plugin

A **Plugin** is Downcity's single extension product unit. It may provide Agent runtime capabilities, its own host-side management logic, and one Mainview without introducing a separate Extension identity.

```text
Plugin
├── agent      optional: Agent runtime capability
├── main       optional: management logic and actions
└── renderer   optional: the single Mainview
```

## What a plugin does

- Exposes tools the Agent can call during execution
- Hooks into the Agent lifecycle (start, stop, session events)
- Manages its own state, connections, and background tasks
- Manages Profile configuration in its own Mainview
- Runs inside the Agent process boundary, not as a separate service

A Profile is only a host-provided configuration space under one Plugin. Create or select it on the Plugin page, configure it through that Plugin's Mainview, then let an Agent select the Plugin and Profile. Business configuration never lives in `agent.json`.

## Built-in plugins

Downcity ships several built-in plugins that cover common agent needs:

- **Chat** — connects messaging channels (Telegram, Feishu, QQ, etc.)
- **Task** — schedules and runs background tasks
- **Memory** — persists conversation history and context
- **Contact** — manages user contact lists and relationships
- **Shell** — executes local commands in a sandboxed environment
- **Schedule** — cron-style job scheduling
- **Web** — browses the web and extracts content
- **Skill** — composes reusable tool chains

## Writing a plugin

In the SDK, a Plugin remains a regular TypeScript instance and can be passed directly to an Agent without the install protocol:

```ts
const agent = new Agent({
  id: "coding-pro",
  model,
  plugins: [new GithubPlugin({ token })],
});
```

Add a `plugin.json` with optional `agent`, `main`, and `renderer` entries only when the Plugin must be installed and managed by CLI or Desktop.
