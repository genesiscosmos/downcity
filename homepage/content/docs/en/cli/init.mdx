# Project Init

`city agent create` creates Workspace runtime and Skills directories, stores Agent and Workspace as independent global entities, and persists the Agent's single Workspace binding. It does not generate an Agent declaration file in the Workspace.

```bash
city agent create
```

Without a path, the interactive flow lets you use the current directory or open the operating system's native folder picker. Pass a relative or absolute path to skip that choice:

```bash
city agent create .
city agent create ./my-project
city agent create /absolute/path/to/my-project
```

Generated structure:

```text
my-project/
├── .env
├── .agents/
│   └── skills/
└── .downcity/
```

The global database stores Agent ID, Workspace binding, model, and Plugin config. Project `.env` overrides Global Env from `~/.downcity/.env`; explicit process environment variables have the highest priority.

```bash
# Allow replacing existing Agent config in the global database
city agent create ./my-project --force
```

After initialization, add project Skills under `.agents/skills`, inspect the generated `agent_id` with `city agent list`, then run `city agent chat <agent_id>` directly or use `city on` for the long-running City host.
