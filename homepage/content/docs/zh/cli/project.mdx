# 项目结构

Agent 的管理配置统一保存在全局数据库。Agent 不需要项目声明文件；项目目录只作为 Workspace，保留环境、Skills 和业务运行数据。

## 目录布局

```text
my-project/
├── .env                 # 项目环境变量
├── .agents/
│   └── skills/          # 用户管理、可进入版本控制的 Skills
├── .downcity/           # Agent 与 Plugin 运行数据
│   ├── agents/          # 会话与消息数据
│   ├── chat/            # Chat Access、路由和历史数据
│   ├── logs/            # 运行日志
│   ├── memory/          # 记忆数据
│   └── task/            # 任务运行数据
└── src/                 # 业务代码（可选）
```

## 全局配置

默认保存在 `~/.downcity/downcity.db`，设置 `DC_PLATFORM_ROOT` 后改为 `$DC_PLATFORM_ROOT/downcity.db`。其中包含：

- 独立的 Agent ID、Workspace ID、项目路径和启动参数
- 模型绑定与 Plugin 配置
- Plugin Resource 与 Agent Plugin Binding
- City 登录态和其他平台管理状态

CLI、交互管理器和 Agent daemon 都读取同一份数据库，不维护项目配置副本。

`agent_id` 与 `workspace_id` 分别是 Agent 和 Workspace 的全局主键。Registry 不保存二者的永久绑定；CLI 或 Desktop 在运行时显式组合 `agent_id + workspace_path`。同一个 Agent 可以在不同 Workspace 运行，同一个 Workspace 也可以运行不同 Agent。CLI daemon 的本次实际 Workspace 记录在 `~/.downcity/runtimes/<agent_id>/daemon.json`，Session 保存在实际 Workspace 的 `.downcity/agents/<agent_id>/sessions/` 下。

## 项目资产

Global Env 单独保存在 `~/.downcity/.env`。项目 `.env` 覆盖 Global Env，启动进程显式环境变量拥有最高优先级；项目 `.env` 默认加入 `.gitignore`。`.agents/skills` 是项目中唯一由用户管理并进入版本控制的 Agent 能力资产。

## 运行数据

`.downcity/` 只保存会话、Chat Access、任务、记忆和缓存等业务运行数据。不要把管理配置、PID 或 daemon 元数据写入该目录。
