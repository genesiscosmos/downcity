# Task 插件

Task 插件让 Agent 能够调度和运行后台任务。它适用于定期数据获取、报告生成，或任何应该在正常请求-响应流之外发生的工作。

## 功能

- 在特定时间或间隔调度任务
- 在 Agent 重启后持久化任务状态
- 处理重试和失败恢复
- 提供延迟任务队列

## Desktop 工作区

Task 不声明 Config，因此不需要 Profile。它仍会出现在 Plugins Catalog 中展示说明，同时在一级导航条贡献独立入口。Plugin Sidebar 使用 `Agent → Task → 执行记录` 三级树；点击 Task 查看任务详情，展开 Task 时才读取执行记录。Mainview 用于查看任务定义、最终输出、执行状态、触发来源、耗时、结果校验和错误信息。

Desktop 可以直接新建、编辑、启用、暂停、立即运行和删除 Task。Workspace 不是页面筛选器，而是每个 Task 自身的执行配置；手动与定时执行始终使用该 Task 绑定的唯一 Workspace。这里直接使用所选 Agent 的 Task runtime 与既有 run 产物，不保存第二份任务状态。

Task 成功或失败并完成执行记录持久化后，会通过统一 Notification 模块产生未读通知；跳过的执行不会通知。同一 Agent 的同一 Task 只保留最新未读 Run。Desktop 会在 Task 一级图标、Task 条目和对应 Run 旁显示蓝点，并同步系统应用图标角标；打开该 Run 后自动标记为已读。

## 定义任务

任务在项目定义中，并在启动时向 Task 插件注册。它们可以通过以下方式触发：

- Cron 表达式
- 一次性调度
- 事件驱动触发

## 使用场景

- 每日数据同步
- 定期报告生成
- 后台文件处理
- 定时通知

任务执行时会创建独立的 task Session，并复用宿主 Agent 的能力。从 Agent Session 调用 `create` 时，运行时会直接捕获当前 `session_id` 与 `origin.type`，Task 完成后把结果作为 assistant 消息追加回该 Session；模型无需也不能填写 Session 路由。通过 CLI、HTTP 或宿主管理界面等无 Session 上下文入口创建的 Task 不绑定交付目标，结果保留在执行历史。任务 Agent 如需发送聊天消息，应在 task Session 内主动调用 Chat 插件。
