# 自定义插件

一个第三方目录只定义一个 Plugin。Plugin 的全局唯一 ID 同时是最终目录名、Agent 引用键和运行时 Registry key。

## 开发目录

```text
github-plugin/
├── src/index.ts
├── plugin.json
├── package.json
├── tsconfig.json
└── dist/index.js
```

`src/` 和 `tsconfig.json` 只服务本地开发。Downcity 不规定构建工具，也不需要 `tsup.config.ts`。`package.json` 属于 Plugin 包，用来声明明确的 ESM package 边界，因此必须包含 `"type": "module"` 并会随 Plugin 安装。构建脚本只需把入口及其运行时依赖打包成一个自包含 ESM 文件；例如可直接在 `package.json` 中调用 esbuild：

```json
{
  "type": "module",
  "scripts": {
    "build": "esbuild src/index.ts --bundle --platform=node --format=esm --outfile=dist/index.js"
  }
}
```

ESM 入口通过 `plugin` 命名导出 Plugin constructor：

```ts
export const plugin = GithubPlugin;
```

## Plugin constructor

```ts
import type { Plugin, PluginActions } from "@downcity/agent";

export interface GithubPluginConfig {
  api_url: string;
  token: string;
}

export class GithubPlugin implements Plugin {
  readonly name = "github";
  readonly title = "GitHub";
  readonly description = "GitHub 集成";
  readonly actions: PluginActions;

  constructor({ config }: { config: GithubPluginConfig }) {
    this.actions = {};
  }
}

export const plugin = GithubPlugin;
```

实例 `name`、`plugin.json` 的 `id`、目录名和 Agent 引用必须一致。constructor 不重复声明 Manifest 或运行时 Schema；TypeScript 类型只服务 Plugin 代码，profile 的运行时协议由 `plugin.json.config.schema` 定义：

```ts
new PluginConstructor(selected_profile);
```

Loader 先使用 JSON Schema 校验 profile，再把完整 profile 直接传入 constructor。运行时 Client 和 Provider 由 Plugin 内部创建；Agent 级服务通过 Plugin 执行上下文读取。框架不定义 Binding、Resource、Resolver 或 Installation 持久化领域。

## Plugin 定义

源目录只保留一个 `plugin.json`：

```json
{
  "schema_version": 1,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub 集成",
  "icon": "./assets/github.svg",
  "entry": "dist/index.js",
  "config": {
    "schema": {
      "type": "object",
      "properties": {
        "api_url": { "type": "string", "format": "uri" },
        "token": { "type": "string", "minLength": 1, "writeOnly": true }
      },
      "required": ["api_url", "token"],
      "additionalProperties": false
    }
  }
}
```

`icon` 可选，支持 `http://`、`https://` 远程地址，或 Plugin 根目录内的相对路径。相对路径对应的文件会随安装复制，并且不能使用 symlink 或路径逃逸。

`README.md` 是第三方 Plugin 的必需文件，安装后会保留在 Plugin 目录，供 CLI、Desktop 和用户离线查看。

配置 `schema` 使用 JSON Schema 2020-12。常用字段包括：

- `type`、`properties`、`required`、`additionalProperties`
- `enum`、`const`、`oneOf`、`anyOf`、`allOf`
- 字符串的 `minLength`、`maxLength`、`pattern`、`format`
- 数值的 `minimum`、`maximum`、`multipleOf`
- 数组的 `items`、`minItems`、`maxItems`、`uniqueItems`
- `default`、`examples`、`title`、`description`
- 敏感字段使用 `writeOnly: true`

例如：

```json
{
  "type": "object",
  "properties": {
    "endpoint": {
      "type": "string",
      "format": "uri"
    },
    "mode": {
      "type": "string",
      "enum": ["safe", "fast"],
      "default": "safe"
    },
    "token": {
      "type": "string",
      "minLength": 1,
      "writeOnly": true
    }
  },
  "required": ["endpoint", "token"],
  "additionalProperties": false
}
```

表单展示所需的占位符、排序或控件提示放在 `x_downcity` 下，不改变 JSON Schema 的运行时校验语义。

运行时默认配置只取 `plugin.json.config.defaults`。字段级 `default` 保留为 JSON Schema 注解，供表单或文档展示，不会自动写入 profile。

Plugin 作者直接在 `plugin.json` 中声明完整 JSON Schema 和可选 `defaults`。安装器校验 Schema、默认值与已有 profile，并把来源、完整性和时间信息写回安装后的同一个文件；不会生成第二份 Manifest 或 Schema 快照。

`entry` 必须指向单个自包含 ESM 文件。安装器不会执行依赖安装、构建脚本或导入 Plugin 入口，也不会复制入口之外的源码和开发文件。Plugin 使用 Zod 等运行时依赖时，构建工具必须把依赖打进入口。

安装后的目录是确定的：

```text
~/.downcity/plugins/github/
├── plugin.json
├── config.toml
├── package.json
├── README.md
├── assets/github.svg
└── dist/index.js
```

`config.toml` 只保存命名的明文 profile 值，文件权限为 `0600`。CLI 与 Desktop 使用 `plugin.json` Schema 构建表单，并脱敏 `writeOnly` 字段。

```toml
schema_version = 1

[profiles.production]
api_url = "https://api.github.com"
token = "plain-local-token"
```

Agent 显式选择的 profile 不存在时会报错；没有显式选择时读取 `default` profile，不存在则使用 `plugin.json.config.defaults` 或空对象，再执行 Schema 校验。

## 安装与配置

```bash
city plugin install ./github-plugin
city plugin config github production --interactive
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

更新会原子替换整个 Plugin 目录并保留 `config.toml`。新 Schema 无法校验已有 profile 时更新失败；仍被 Agent 引用的 profile 或 Plugin 不能删除。

安装过程只读取并复制 `plugin.json`、`package.json` 与声明的入口，不会执行 `npm install`、构建脚本、Plugin lifecycle 或入口模块。constructor 的导出与实例 ID 在 Agent 真正加载 Plugin 时验证；`package.json` 与入口会生成 SHA-256 摘要。只应安装可信来源。
