# 自定义插件

CLI Plugin 是一个预构建的静态制品。仓库使用 JSON Manifest 描述入口和配置协议；安装后，City 将 Plugin 加入统一 Catalog，并为每个 Agent 单独保存启用状态和配置。

## 制品结构

```text
example-plugin/
├── downcity.plugin.json
└── dist/
    ├── index.js
    ├── config.schema.json
    └── resource.schema.json
```

`downcity.plugin.json`：

```json
{
  "manifest_version": 1,
  "name": "example",
  "version": "1.0.0",
  "entry": "dist/index.js",
  "title": "Example",
  "description": "一个示例 Plugin",
  "config": {
    "schema": "dist/config.schema.json",
    "defaults": {
      "endpoint": "https://example.com"
    }
  },
  "resources": {
    "schema": "dist/resource.schema.json"
  }
}
```

Manifest 必须是静态 JSON。`entry`、`config.schema` 和 `resources.schema` 都是相对仓库根目录的路径，且不能指向目录外或符号链接。没有 Resource 的 Plugin 可以省略 `resources`。

## 配置协议

配置协议使用 JSON Schema 2020-12。你可以在源码中使用 Zod 定义配置，并在构建阶段输出 JSON Schema：

```ts
import { z } from "zod";

export const config_schema = z.object({
  endpoint: z.url(),
}).strict();

const json_schema = z.toJSONSchema(config_schema, {
  target: "draft-2020-12",
});
```

构建脚本需要将 `json_schema` 写入 `dist/config.schema.json`。City 安装时使用 Ajv 校验 Schema 和默认值，配置时再用同一 Schema 校验 Agent Binding。Zod 不是运行期协议，也不应写进 Manifest。

## Resource Schema 与 Resolver

Resource Schema 描述一个完整 Item，并要求 `id`、`type`、`name`。`id` 必须是 `readOnly`；其他 `readOnly` 顶层字段由 Resolver 写入，`writeOnly` 字段由用户安全输入并在 CLI 输出时脱敏。

```json
{
  "title": "API Account",
  "type": "object",
  "required": ["id", "type", "name", "api_key"],
  "properties": {
    "id": { "type": "string", "readOnly": true },
    "type": { "type": "string", "const": "api" },
    "name": { "type": "string", "readOnly": true },
    "api_key": { "type": "string", "writeOnly": true }
  },
  "additionalProperties": false
}
```

Resolver 返回全部动态字段投影，不能修改 `id`、`type` 或用户字段：

```ts
resolve_resource({ resource }) {
  return { name: inspect_name(String(resource.api_key)) };
}
```

## Runtime Factory

入口必须导出 `plugin_factory`，也可以使用默认导出。Factory 接收已校验的 Agent `config` 和 Resource ID 解析出的完整 `resources`：

```ts
import type { JsonObject, Plugin } from "@downcity/agent";

export const plugin_factory = {
  async resolve_resource({ resource }: { resource: JsonObject }) {
    return { name: await resolve_name(resource) };
  },

  create({ config, resources }: {
    config: JsonObject;
    resources: JsonObject[];
  }): Plugin {
    return {
      name: "example",
      title: "Example",
      description: `${String(config.endpoint)} · ${resources.length} resources`,
      actions: {},
    };
  },
};
```

Factory 返回的 `name` 必须与 Manifest 的 `name` 一致。`dist/index.js` 必须是自包含 ESM；运行期依赖需要打包进制品，`@downcity/agent` 只能作为编译期类型依赖使用。

## 安装与配置

```bash
# 本地目录
city plugin install ./example-plugin

# Git URL，可附带 branch 或 tag
city plugin install https://github.com/acme/example-plugin.git#v1.0.0

# GitHub 简写
city plugin install github:acme/example-plugin#main

city plugin update example
city plugin resource create example --interactive
city plugin resource list example
city plugin config example my-agent --interactive
city plugin config example my-agent --resources '["api-a1b2c3"]'
city plugin enable example my-agent
```

也可以使用 `city plugin` 打开管理面板，完成安装、更新、选择 Agent、配置和启停。配置变更后，需要重启正在运行的 Agent 才会进入新的 Runtime。

## 安全边界

安装过程只读取 Manifest、JSON Schema 和静态文件，不执行 `npm install`、构建脚本、生命周期脚本或 Plugin entry。City 会记录 Git commit（Git 来源）和完整制品的 SHA-256 摘要。

Plugin entry 会在创建、编辑或刷新 Resource，以及 Agent 启动时执行，因此只应安装可信来源。安装期静态检查不能替代对第三方运行时代码的审查。
