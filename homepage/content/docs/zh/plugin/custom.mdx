# 自定义插件

一个目录只定义一个 Plugin。Plugin ID 同时是安装目录名、Agent 引用键和运行时身份，不需要再声明 Extension。

## 三个可选入口

```text
Plugin
├── agent      为 Agent 创建运行实例
├── main       提供宿主管理逻辑与 actions
└── renderer   提供唯一 Mainview
```

三个入口都可选，但至少提供一个。一个 Plugin 可以只提供 Agent 能力，也可以只提供 Mainview，或同时提供完整的运行与配置体验。

推荐的开发目录：

```text
github-plugin/
├── plugin.json
├── package.json
├── README.md
├── assets/icon.svg
├── src/
│   ├── plugin.ts
│   ├── agent.ts
│   ├── main.ts
│   └── renderer.tsx
└── dist/
    ├── agent.js
    ├── main.js
    └── renderer.js
```

三个入口都使用 ESM。`agent.js` 与 `main.js` 必须自包含；`renderer.js` 是单文件浏览器 bundle，默认导出唯一 React Mainview。Downcity 不安装依赖或运行构建脚本。

## 直接用于 SDK

Plugin Class 的 constructor 完全由作者决定。SDK 用户可以直接创建实例，不经过 `plugin.json` 或 Profile：

```ts
const github_plugin = new GithubPlugin({
  api_url: "https://api.github.com",
  token: process.env.GITHUB_TOKEN ?? "",
});

const agent = new Agent({
  id: "coding-pro",
  model,
  plugins: [github_plugin],
});
```

只有需要被 CLI 或 Desktop 安装、发现和管理时，才需要下面的入口协议。

## Plugin 定义

```json
{
  "schema_version": 1,
  "id": "github",
  "version": "1.0.0",
  "title": "GitHub",
  "description": "GitHub 集成",
  "icon": "./assets/icon.svg",
  "agent": "./dist/agent.js",
  "main": "./dist/main.js",
  "renderer": "./dist/renderer.js"
}
```

`package.json` 必须声明 `"type": "module"`。`README.md` 是必需的用户文档，Desktop 会在 Plugin Overview 中安全渲染它；应写清用途、配置方式和必要凭据。图标可以是 HTTP(S) 地址或 Plugin 根目录内的相对文件，并会用于 Plugin 导航与 Overview。

## Agent 入口

`agent` 默认导出 factory。宿主为每个 Agent 调用一次并传入所选 Profile 的配置快照：

```ts
import type { AgentPluginModule } from "@downcity/agent";
import { GithubPlugin } from "./plugin.js";

const create_agent_plugin: AgentPluginModule<GithubPlugin>["default"] = (context) => {
  return new GithubPlugin(context.profile as unknown as GithubPluginConfig);
};

export default create_agent_plugin;
```

每次调用必须返回新的 Plugin 实例，实例 `name` 必须等于 `plugin.json.id`。factory 只是宿主装配适配器，不负责安装，也不替代 Agent Plugin 的 `start/stop` 生命周期。

## Main 入口

`main` 默认导出生命周期对象。它注册 Mainview 可调用的 actions，并由 Plugin 自己完成配置校验和凭据保护：

```ts
import { define_plugin_main } from "@downcity/plugin";

export default define_plugin_main({
  activate({ plugin }) {
    plugin.action({
      id: "profile.read",
      run: async (_input, context) => {
        const config = await context.config.get();
        return { api_url: config.api_url, token_configured: Boolean(config.token) };
      },
    });

    plugin.action({
      id: "profile.save",
      run: async (input, context) => {
        const current = await context.config.get();
        const config = validate_and_restore_secret(input, current);
        await context.config.set(config);
        return { saved: true };
      },
    });
  },
});
```

一个 main 在宿主中只激活一次。当前 Profile 只在 action 调用时注入，所以同一个 main 可以安全服务多个 Profile。不要把 Profile 缓存在全局变量中。

## Mainview 入口

Mainview 是 Plugin 唯一的前端插槽。Renderer 默认导出一个 React 组件，并组合宿主提供的 UI Components：

```tsx
import { useEffect, useState } from "react";
import { define_plugin_renderer } from "@downcity/plugin/react";

export default define_plugin_renderer(function GithubMainview({ plugin, ui }) {
  const { Button, Group, Input, LoadingState, Page, Row, Toolbar } = ui.components;
  const [profile, set_profile] = useState<{ api_url: string }>();

  useEffect(() => {
    void plugin.invoke<{ api_url: string }>("profile.read").then(set_profile);
  }, [plugin]);

  if (!profile) return <LoadingState label="正在读取 Profile…" />;
  return <Page>
    <Toolbar title="GitHub" actions={<Button variant="primary" on_click={() => void plugin.invoke("profile.save", profile).then(() => ui.toast({ type: "success", message: "已保存" }))}>保存</Button>} />
    <Group>
      <Row label="API URL" trailing={<Input value={profile.api_url} on_value_change={(api_url) => set_profile({ ...profile, api_url })} />} />
    </Group>
  </Page>;
});
```

Renderer bundle 必须把 `react` 与 `react/jsx-runtime` 保留为宿主外部依赖，并分别映射到 `downcity-plugin://runtime/react` 与 `downcity-plugin://runtime/react/jsx-runtime`。其他前端依赖应打包进同一个 `renderer.js`。

Desktop 在宿主 React 树中加载 Renderer，并绑定当前 Plugin/Profile。组件只通过属性获得 `plugin.invoke()`、`ui.components`、Toast 和 Confirm，不会获得 Profile ID 或 Desktop controller。Renderer 属于受信任本地 UI 代码；只安装可信来源。外链、剪贴板、文件定位和业务读写应通过 main 的明确 action 完成。

## Profile 交互

```text
进入 Plugin
→ 创建或选择 Profile
→ 在 Mainview 中配置
→ Agent 启用 Plugin 并选择 Profile
```

Profile 只是宿主提供的配置空间。宿主统一负责创建、选择、删除和持久化，不解释字段，也不根据 JSON Schema 生成表单。内容结构、校验、默认值和 Secret 行为都属于 Plugin。

配置保存在 `~/.downcity/plugins/<plugin_id>/config.toml`，目录权限为 `0700`，文件权限为 `0600`。当前存储使用 TOML，因此配置必须是 TOML 可表达的 JSON object。Agent 的 `agent.json` 只保存 Profile 引用；多个 Agent 可以显式复用同一 Profile。

## 安装

```bash
city plugin install ./github-plugin
# 在 Desktop 的 GitHub Plugin 页面创建并配置 production
city plugin enable github my-agent --profile production
city plugin update github
city plugin uninstall github
```

安装器只复制 `plugin.json`、`package.json`、`README.md`、声明的入口和可选本地图标，不执行依赖安装、构建脚本或任何入口。入口不能逃逸 Plugin 根目录或使用 symlink，安装制品会生成 SHA-256 完整性摘要。只安装可信来源。
