# Chat 插件

Chat 插件将 Agent 连接到 Telegram、飞书、QQ 等聊天渠道。它处理收到的消息，将它们路由到 Agent 会话，并将回复发送回渠道。

## 功能

- 监听已配置渠道的消息
- 为每个对话创建或复用会话
- 将用户消息路由到 Agent
- 将 Agent 回复发送回渠道
- 在消息进入 Agent 前执行按 Agent 隔离的 Chat Access 准入

## 配置

Chat 在 `~/.downcity/plugins/chat/config.toml` 中拥有一份 City 级配置。它包含入站目标、队列行为和渠道：

```toml
schema_version = 2

[config]
owner_agent_id = "assistant"
owner_workspace_id = "project"

[config.queue]
max_concurrency = 4

[[config.channels]]
id = "telegram_primary"
type = "telegram"
name = "Primary Bot"
bot_token = "123456:token"
```

在 Desktop 的 Plugins Catalog 中打开 Chat Config 即可编辑。City 自动把 Chat 能力提供给全部 Agent；
`owner_agent_id` 和 `owner_workspace_id` 只确定外部渠道入站消息的执行目标，不是 Plugin 绑定。

## 渠道凭据

渠道凭据明文保存在 `config.toml`，通过仅当前用户可访问的目录与文件权限保护（`0700` 和 `0600`）。Chat Config 通过 Chat 自己的 Config actions 读取和保存配置；读取不会返回 `bot_token`、`app_secret` 原文，编辑时留空会保留已有凭据。保存后 Chat 会停止旧渠道与队列，下一次使用时按新配置惰性重建。

## Chat Access

外部用户第一次发送消息时，Chat Plugin 会在当前 Agent 的 `.downcity/chat/access.db` 中记录 Principal，并在没有 Grant 时创建 pending Request。管理员使用 Request ID 批准或拒绝：

```bash
city plugin action chat access-snapshot <agent_id> --input '{}' --token <token>
city plugin action chat access-approve <agent_id> --input '{"request_id":"<request_id>"}' --token <token>
```

身份由唯一配置中的渠道 ID 和平台用户 ID 共同确定。批准只对目标 Agent 生效，不会成为 City 全局权限，也不会传播到其他 Plugin。

## 支持的渠道

- Telegram
- 飞书 (Lark)
- QQ

## 飞书依赖

`@downcity/plugins` 默认不再安装飞书 / Lark SDK。如果你在本地嵌入 SDK 宿主中启用飞书渠道，需要在宿主应用里安装：

```bash
npm install @larksuiteoapi/node-sdk@^1.66.0
```

使用 Chat plugin 的独立子路径：

```ts
import { ChatPlugin, FeishuChannel } from "@downcity/plugins/chat";
```

不启用飞书的应用不需要安装飞书 SDK。
