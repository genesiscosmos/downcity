---
title: 架构
description: "Downcity 的核心分层：console、agent、execution context、session 与 Power runtime"
---
当前 Downcity 最好通过五层来理解：

1. `console`
2. `agent`
3. `execution context`
4. `session`
5. `power runtime`

## 分层

### `console`

- 全局控制面
- 进程 registry
- city 级配置与观测

### `agent`

- 拥有一个项目 runtime
- 持有模型访问、session store、Power registry 与 runtime host 状态

### `execution context`

- 执行期间暴露出来的统一能力面
- Power 读取稳定运行时能力的地方

### `session`

- 拥有一条执行线程与其 prompt / run 状态
- 真正跑 model + tool flow 的执行单元

### `power runtime`

- 当前所有能力模块统一建模成 Power
- 有些是本地 action-first Power
- 有些是托管 lifecycle-owned Power

## 托管 Power 与本地 Power

### 本地 Power

- 通常直接挂到一个 SDK `Agent` 上
- 例如：`skill`、`web`、`sound`

### 长期运行 Power

- 由 `Agent` 在构造时装配，并在 `agent.dispose()` 时释放
- 例如：`chat`、`task`、`memory`、`shell`、`schedule`

## 最重要的结论

不要再用旧的“双层拆分”语言理解当前系统。

现在的真实模型是：

- session 负责执行
- Power 负责暴露能力
- 托管 Power 负责长期运行模块
