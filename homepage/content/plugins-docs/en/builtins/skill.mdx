# Skills

`skill` is an Agent's skill catalog. Each Agent has its own skill directory, and that directory is the authoritative set of skills the Agent can use. The power discovers those skills, reads `SKILL.md`, and injects the inventory into the system prompt.

Skills live at `~/.downcity/powers/skill/agents/<agent-id>/`. Every entry is a directory containing `SKILL.md`. An entry is either a copy installed into the Agent directory or a symlink pointing at a skill that lives elsewhere.

## Scope

The Agent's own directory is the default and authoritative source. Two extra sources are readable on demand:

- `project` reads `<workspace>/.agents/skills`
- `home` reads `~/.agents/skills`
- `all` returns the union of the Agent directory, project, and home

When the same skill ID appears in more than one source, the Agent directory wins, then project, then home.

`list` and `lookup` accept the same `scope` argument, and both default to the Agent directory. The system prompt inventory lists the Agent directory only, so every skill name shown to the model is directly usable without a scope argument.

## Actions

| Action | Payload | Purpose |
| --- | --- | --- |
| `list` | `{ scope?: "agent" \| "project" \| "home" \| "all" }` | List skills in the given scope; defaults to the Agent directory |
| `lookup` | `{ name: string, scope?: ... }` | Read a skill's `SKILL.md` |

`lookup` returns the skill body as a standard context message, so the content reaches the model on the next step. It does not persist any session state.

There are no `find` or `install` actions. Installation and linking are Desktop operations, because writing into the Agent directory is a user decision rather than something the model should do mid-task. The system prompt tells the Agent to ask the user to add a skill from the Skills page when it needs one that is not listed.

Listing the Agent's skills:

```ts
const result = await city.plugins.scope({ agent_id: agent.id, workspace_id: workspace.id }).run_action({
  power: "skill",
  action: "list",
  payload: {},
});
```

Reading a skill:

```ts
const result = await city.plugins.scope({ agent_id: agent.id, workspace_id: workspace.id }).run_action({
  power: "skill",
  action: "lookup",
  payload: {
    name: "web-access",
  },
});
```

The model uses the same protocol inside a Session:

```ts
skill({
  action: "lookup",
  args: {
    name: "web-access",
  },
});
```

## Configuration

Skill has no Config panel. Scope is determined by the Agent directory plus the `scope` argument, so the only constructor option is `ignore`:

```ts
const skill_power = new SkillPower({
  ignore: ["legacy-skill", /^internal-/],
});
```

- A string matches both the skill ID and its name.
- A `RegExp` filters in bulk.
- A predicate returning `true` excludes the skill.

## Desktop

The Skills page is organized by Agent. The Sidebar lists every registered Agent as an expandable root, and expanding one shows the skills bound to that Agent. Selecting an Agent opens its skill configuration; selecting a skill opens its `SKILL.md`.

The Mainview for an Agent has three views:

- **Bound** shows the skills in that Agent's directory, each marked as installed or linked, and each skill can be removed.
- **Catalog** shows every skill from the user directory and each registered Workspace, marked with whether it is already linked to this Agent. Linking creates a symlink in the Agent directory, so the source directory stays untouched.
- **Discover** searches the public catalog through the official `skills` CLI and installs the result into this Agent's directory. Installation stages the download in a temporary directory and copies it in, because the CLI cannot install directly into an Agent directory.

Removing a linked skill deletes only the symlink; removing an installed skill deletes the copy. Both operations stay inside the Agent directory.
