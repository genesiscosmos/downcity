# `chat` Plugin

`chat` 是渠道运行时 plugin。

它主要持有：

- channel state
- chat queue worker
- chat queue store
- chat authorization hooks / resolves
- chat 相关 actions
- chat system text

## 主要形状

- `lifecycle`
- `actions`
- `hooks`
- `resolves`
- `system`

## 它主要解决什么问题

当你需要这些能力时，应该关注 `chat`：

- Telegram、Feishu、QQ 这类 chat 渠道 runtime
- 每个 Chat Profile 共享实例一条 queue worker
- 消息入站后的执行与消息出站发送
- 入站用户授权、主体观测和角色解析

## 用户怎么使用

Chat 在自己的 Config 中管理队列和渠道。先在 Desktop 的 Plugins Catalog 中打开 Chat 详情，创建或选择 Profile，再让 Agent 引用它：

```bash
# 在 Desktop 的 Plugins Catalog / Chat 中配置 primary
city plugin enable chat <agent_id> --profile primary
```

需要从终端调用 Chat Action 时，也使用通用 Plugin Action 命令：

```bash
city plugin action chat send <agent_id> --input '{"chat_key":"telegram:123456","text":"Done"}' --token <token>
```

## SDK 装配

SDK 宿主通过 `CityPluginRegistration` 把 Chat 提供给 City，再用 Profile 配置渠道：

```ts
const registrations = create_builtin_plugin_registrations();
const city = new City({ plugins: registrations, workspaces: [workspace] });
city.agents.add(agent, {
  plugins: [{
    plugin_id: "chat",
    profile: {
      id: "primary",
      config: {
        owner_agent_id: agent.id,
        owner_workspace_id: workspace.id,
        channels: [{
          type: "telegram",
          id: "telegram-main",
          name: "Main Bot",
          bot_token: process.env.TELEGRAM_BOT_TOKEN ?? "",
        }],
      },
    },
  }],
});
const entry = await city.enter_workspace(agent.id, workspace.id);
```

Profile 属于 City 控制面，不进入 Agent。Chat main actions 负责 Profile 校验与凭据安全投影。
同一 Profile 只有一组渠道连接和 queue；跨作用域绑定必须通过 Owner 字段显式选择路由。

## 飞书依赖

`@downcity/plugins` 不再把飞书 / Lark SDK 放进默认生产依赖。不启用飞书的应用可以直接导入 `@downcity/plugins`，无需安装飞书运行时依赖。

如果宿主应用启用了 `FeishuChannel`，需要在宿主应用中安装这个依赖：

```bash
npm install @larksuiteoapi/node-sdk@^1.66.0
```

使用 Chat plugin 的独立子路径：

```ts
import { ChatPlugin, FeishuChannel } from "@downcity/plugins/chat";
```

如果启用了飞书但没有安装 SDK，运行时错误会明确提示需要安装的包，并说明是在启用 channel `"feishu"` 前安装。

## SDK action 用法

本地嵌入 SDK 场景里，可以按 plugin 名称调用会话 action：

```ts
await entry.plugins.run_action({
  plugin: "chat",
  action: "send",
  payload: {
    chat_key: "telegram:123456",
    text: "Done",
  },
});
```

常用 action 是 `list`、`info`、`send`、`react`、`context`、`history`、`delete`。

## 内置授权能力

Chat 授权现在属于 `ChatPlugin` 自己，不需要额外挂一个独立授权 plugin。

它通过三个 chat plugin 点参与入站链路：

- `chat.observePrincipal`：记录已观测到的用户和会话
- `chat.authorizeIncoming`：根据角色与权限决定当前消息是否允许进入 agent
- `chat.resolveUserRole`：为 history / queue metadata 补齐当前用户角色

授权 action 也挂在 `chat` 下：

| Action | 作用 |
| --- | --- |
| `authorization-snapshot` | 读取授权目录、配置、已观测用户和会话 |
| `authorization-read-config` | 读取当前授权配置 |
| `authorization-write-config` | 覆盖写入授权配置 |
| `authorization-set-user-role` | 设置某个渠道用户的角色 |

SDK 调用示例：

```ts
await entry.plugins.run_action({
  plugin: "chat",
  action: "authorization-set-user-role",
  payload: {
    channel: "telegram",
    userId: "12345678",
    roleId: "admin",
  },
});
```

## 关键运行语义

- 渠道连接与 queue worker 归属于 City 持有的 Chat Profile 共享实例
- Agent/Workspace 路由在 `bind/unbind` scope 生命周期中建立和释放
- 入站授权能力归属于 `ChatPlugin`，但仍通过通用 plugin hooks / resolves 调度
- `Agent` 只声明 Chat/Profile 绑定，不持有 chat 领域长期状态

## 公开性说明

`ChatPlugin` 从 `@downcity/plugins` 包根导出。

SDK 用户通过 City registration/Profile 装配它，不把 `ChatPlugin` 实例交给 Agent。
