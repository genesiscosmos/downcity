# `memory` Plugin

`memory` 为 Agent 提供长期记忆。所有存储、权限、召回和上下文组装逻辑都在 `MemoryPlugin` 内；City 只提供共享 Memory 根目录。

## Memory 范围

| 范围 | 用途 | 可见性 |
|---|---|---|
| `current_user` | 用户资料和偏好 | 同一 City 中的同一认证用户跨 Agent 共享 |
| `current_workspace` | 项目事实和决策 | 同一 Workspace 跨 Agent 共享 |
| `agent` | Agent 私有经验和长期状态 | 仅当前 Agent |

User Memory 只使用 Embassy 返回的认证用户身份。没有认证身份时，`current_user` 写入会失败，不会退化到默认用户或 Agent Memory。

## 上下文行为

- Core Memory 作为独立命名的 `system` block，在 Session system snapshot 中冻结。
- Dynamic Recall 每个 Turn 最多执行一次，放入当前 User Message 的模型输入副本。
- Tool Loop 和上下文超限重试复用同一份 Recall。
- Recall 不写回 canonical Session Messages，也不会获得 system instruction 权限。
- 成功 Turn 的 canonical User/Assistant 文本会形成幂等 Capture Job；失败、停止、寒暄和明显敏感内容会被跳过。

## Actions

Plugin 提供：`status`、`search`、`read`、`remember`、`digest`、`revise` 和 `forget`。

显式记忆必须选择有限语义目标：

```json
{
  "content": "用户偏好简洁回答。",
  "target": "current_user",
  "topic": "user-preferences",
  "memory_type": "preference"
}
```

`remember` 返回完整逻辑 `memory_id`。后续 `read`、`revise` 和 `forget` 应原样使用该 ID，不要解析为物理路径。

## 存储

内建 City 装配使用两个独立根目录：

```text
~/.downcity/agents/<agent_id>/plugins/memory/  # Agent 私有 Memory
~/.downcity/memory/                            # City 共享 Memory
```

原始 `user_id`、`workspace_id` 和 `agent_id` 会编码成安全路径段。多个 Agent 可以指向同一个 City 根目录，但 User 与 Workspace 内容仍按 Subject 隔离。

直接使用 SDK 时可以显式装配：

```ts
const memory = new MemoryPlugin({
  agent_root_path: "/absolute/path/to/agent-memory",
  city_root_path: "/absolute/path/to/city-memory",
});
```

省略 `city_root_path` 时只启用 Agent Memory。
