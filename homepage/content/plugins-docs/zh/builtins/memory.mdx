# `memory` Plugin

`memory` 为多个 Agent 提供长期记忆。City 持有共享 Plugin 实例并分配私有存储根目录；所有权限、召回和上下文组装逻辑都在 `MemoryPlugin` 内。

## Memory 范围

| 范围 | 用途 | 可见性 |
|---|---|---|
| `current_user` | 用户资料和偏好 | 同一 City 中的同一认证用户跨 Agent 共享 |
| `current_workspace` | 项目事实和决策 | 同一 Workspace 跨 Agent 共享 |
| `agent` | Agent 私有经验和长期状态 | 仅当前 Agent |

User Memory 只使用 Embassy 返回的认证用户身份。没有认证身份时，`current_user` 写入会失败，不会退化到默认用户或 Agent Memory。

## 上下文行为

- Core Memory 作为独立命名的 `system` block，在 Session system snapshot 中冻结。
- Dynamic Recall 每个 Turn 最多执行一次，放入当前 User Message 的模型输入副本。
- Tool Loop 和上下文超限重试复用同一份 Recall。
- Recall 不写回 canonical Session Messages，也不会获得 system instruction 权限。
- 成功 Turn 的 canonical User/Assistant 文本会形成幂等 Capture Job；失败、停止、寒暄和明显敏感内容会被跳过。

## Actions

Plugin 提供：`status`、`list`、`search`、`read`、`remember`、`digest`、`revise` 和 `forget`。

`list` 按当前访问上下文枚举可读记忆，无需关键词；可选的 `subject_kinds`、`memory_types`、
`include_evidence`、`limit` 与 `offset` 用于过滤和分页。`search` 需要关键词，适合按相关性召回。

显式记忆必须选择有限语义目标：

```json
{
  "content": "用户偏好简洁回答。",
  "target": "current_user",
  "topic": "user-preferences",
  "memory_type": "preference"
}
```

`remember` 返回完整逻辑 `memory_id`。后续 `read`、`revise` 和 `forget` 应原样使用该 ID，不要解析为物理路径。

## Desktop 工作区

Memory 不声明 Config。它会在一级导航条贡献独立入口，提供 Sidebar 与 Mainview：

- **Agents**：列出所有已登记 Agent；选择后工作区绑定到该 Agent 及其首个 Workspace。
- **范围**：列出全部可读记忆与各 Subject 的数量（`Agent`、`User`、`Workspace`、`City`）；选择范围会过滤列表，并决定新记忆的写入目标。
- **Mainview**：按关键词与类型筛选，可按查询召回，并把任意记忆打开为 Markdown 详情页，展示 `memory_id`、类型、Subject、观察时间、引用与证据来源；新建、修订与删除都在同一处完成。

所有读写都通过宿主 action 在所选 Agent 与 Workspace 上执行，因此工作区展示的内容与 Agent 实际可读的内容一致。

## 存储

City 为 MemoryPlugin 唯一实例分配一个生命周期根目录，Provider 在内部按 City、Agent、User 与
Workspace 逻辑作用域隔离：

```text
<city-storage>/plugins/memory/
```

原始 `user_id`、`workspace_id` 和 `agent_id` 会编码成安全路径段。多个 Agent 可以指向同一个 City 根目录，但 User 与 Workspace 内容仍按 Subject 隔离。

直接构造即可；`MemoryPlugin.initialize()` 从 City 的 `PluginLifecycleContext.storage` 初始化
Provider：

```ts
const memory_plugin = new MemoryPlugin();
const city = new City({ plugins: [memory_plugin] });
```

不要从 Agent Session 目录推导 Memory 路径；物理布局属于 City 与 Provider。
