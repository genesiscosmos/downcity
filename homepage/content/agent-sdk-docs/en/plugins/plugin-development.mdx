# Plugin Development

Plugin author APIs live in `@downcity/city/plugin`. One `CityPluginModule` defines both the main lifecycle
and the Profile execution-instance factory. The Agent package no longer exports author contracts.

## Execution instance

```ts
import { BasePlugin, create_action } from "@downcity/city/plugin";
import { z } from "zod";

class ExamplePlugin extends BasePlugin {
  readonly name = "example";
  readonly title = "Example";
  readonly description = "An example Plugin.";

  constructor(private readonly client: ExampleClient) {
    super();
  }

  readonly actions = {
    status: create_action({
      description: "Return the current scope.",
      input_schema: { zod: z.object({}) },
      execute: async ({ context, execution }) => ({
        success: true,
        data: {
          agent_id: context.agent.id,
          workspace_id: context.workspace.id,
          session_id: context.session?.id ?? null,
          call_id: execution.call_id,
        },
      }),
    }),
  };
}
```

Use `context.workspace.files` for user Workspace files and `context.storage.files` for private Plugin
state. `context.session` and `context.agent.sessions` are directly callable restricted handles; a
Plugin does not need to resolve objects from IDs alone.

## Unified City module

```ts
import { define_city_plugin } from "@downcity/city/plugin";

export default define_city_plugin({
  activate(context) {
    context.plugin.action({
      id: "about",
      run: () => ({ name: "example" }),
    });
  },
  create({ profile }) {
    return new ExamplePlugin(new ExampleClient(profile.config));
  },
});
```

An SDK host places the module in a `CityPluginRegistration`, provides it to City, and binds Agents by
ID:

```ts
const registration = {
  id: "example",
  title: "Example",
  description: "An example Plugin.",
  readme: "/absolute/path/README.md",
  has_config: false,
  has_sidebar: false,
  has_mainview: false,
  module: example_module,
};

const city = new City({ plugins: [registration], workspaces: [workspace] });
city.agents.add(agent, { plugins: [{ plugin_id: "example" }] });
```

## Lifecycle

`start/stop` belong to City's shared `(plugin_id, profile_id)` instance. `bind/unbind` belong to an
Agent/Workspace scope. Put Profile clients, connections, and caches in `start/stop`; put schedulers,
routes, or scope workers in `bind/unbind`. Every asynchronous Action should propagate
`execution.abort_signal`.

## Installable package

```text
example-plugin/
├── plugin.json
├── package.json
├── README.md
├── dist/main.js
└── dist/renderer.js
```

```json
{
  "schema_version": 1,
  "id": "example",
  "version": "1.0.0",
  "description": "A small example Plugin.",
  "readme": "./README.md",
  "main": "./dist/main.js",
  "renderer": {
    "entry": "./dist/renderer.js",
    "sidebar": true,
    "mainview": true,
    "config": false
  }
}
```

`main` default-exports the `CityPluginModule`; there is no separate `agent` entry. A Renderer
communicates only through the host action gateway and cannot access Node, Electron, Agent objects, or
Profile files directly.

## Testing focus

- Multiple Agents sharing one Profile create and `start` one instance.
- Every Agent/Workspace scope runs exactly one `bind/unbind` pair.
- `stop` waits for the final execution lease.
- Concurrent main calls activate once, and shutdown fully deactivates it.
- Action input, JSON results, and cancellation signals remain valid.
