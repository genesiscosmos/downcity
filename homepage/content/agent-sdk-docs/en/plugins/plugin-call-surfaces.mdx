# Plugin Call Surfaces

Plugins expose four call surfaces for different callers:

| Surface | Caller | Purpose |
| --- | --- | --- |
| `city.plugins` | Host application | Register modules, manage Agent/Profile bindings, invoke main/config actions |
| `entry.plugins` | Host execution code | Call Actions, Availability, or Hooks in one Agent/Workspace scope |
| `context.city.plugins` | Plugin code | Call another Plugin Action, pipeline, or effect in the current scope |
| `plugin_call` | Model in a Session | Call a Plugin Action bound to the current Agent |

## City binding surface

```ts
city.plugins.provide(registration);
await city.plugins.register(agent.id, { plugin_id: "skill" });
console.log(city.plugins.snapshots(agent.id));
await city.plugins.unregister(agent.id, "skill");
```

`city.plugins.invoke()` and `invoke_config()` call host-management Actions registered by Plugin main;
they are not Session execution Actions.

## Workspace execution surface

```ts
const entry = await city.enter_workspace(agent.id, workspace.id);
const result = await entry.plugins.run_action({
  plugin: "skill",
  action: "lookup",
  payload: { name: "frontend-design" },
});
```

This surface explicitly binds an Agent and Workspace, allowing City to create the correct
`PluginContext`.

## PluginContext

```ts
const result = await context.city.plugins.run_action({
  plugin: "skill",
  action: "list",
  payload: {},
});
await context.city.plugins.effect("audit.observe", result.data ?? null);
```

`context.session`, `context.agent.sessions`, and `context.workspace` are directly callable handles.
IDs are reserved for stable identity and serialization.

## Model Tool

```ts
plugin_call({
  plugin: "skill",
  action: "lookup",
  payload: { name: "frontend-design" },
});
```

The Tool is always bound to the current Session's Agent/Workspace execution lease and cannot observe
another Agent's bindings.
