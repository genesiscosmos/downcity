# Plugin Lifecycle

City owns Plugins. An Agent only joins the City; it does not declare Plugin bindings. A City creates
one instance for each Plugin ID and shares it across multiple Agents.

## Registration

```ts
const city = new City({
  workspaces: [workspace],
  plugins: [plugin],
});

city.agents.add(agent);
```

Plugins may also change dynamically:

```ts
city.plugins.add(new ExamplePlugin());
await city.plugins.remove("example");
```

Within a City, one Plugin ID always refers to one instance. Agent-specific configuration is resolved
from the current `PluginContext`.

## Four execution lifecycle checkpoints

- `start(context)` runs once when the Plugin enters City. Use it for shared connections and caches.
- `connect(context)` runs when an Agent enters a Workspace. Use it for scope-specific schedulers, queues, or routes.
- `disconnect(context)` releases that scope when it leaves the Workspace.
- `stop(context)` runs when the Plugin is removed or City closes.

```ts
class SchedulerPlugin extends Plugin {
  readonly name = "scheduler";
  async start({ storage }: PluginStartContext) {
    await this.client.open(storage);
  }
  async connect(context: PluginContext) {
    await this.scheduler.start(context.agent.id, context.workspace.id);
  }
  async disconnect(context: PluginContext) {
    await this.scheduler.stop(context.agent.id, context.workspace.id);
  }
  async stop() {
    await this.client.close();
  }
}
```

`start/stop` receive the same `PluginStartContext`, whose storage belongs to City.
`connect/disconnect` receive the full `PluginContext`, whose storage belongs to the current Agent/Plugin
execution scope.

## Execution leases

A Session captures an immutable Plugin execution view at a Step checkpoint. New Steps stop seeing a
removed Plugin immediately, while an existing Step may finish. City waits for the final lease before
stopping the shared instance, preventing premature shutdown of connections or providers.

`city.close()` releases Workspace scopes, Agents, and Plugin instances. A single `stop` failure
does not prevent other Plugins from cleaning up; City reports an
aggregate error after cleanup finishes.
