# Plugin Configuration

Configuration does not determine Plugin ownership or instance count:

```text
host stores Plugin Profiles
→ City owns one Plugin instance
→ plugin_host.runtime_config(plugin_id, agent_id) projects configuration
→ Plugin reads the current PluginContext.config
```

```ts
const city = new City({
  plugins: [web_plugin],
  workspaces: [workspace],
  plugin_host: {
    runtime_config: (plugin_id, agent_id) => load_runtime_config(plugin_id, agent_id),
    profile_config: (plugin_id, profile_id) => open_profile_store(plugin_id, profile_id),
    notifications: (plugin_id, agent_id) => open_notifications(plugin_id, agent_id),
  },
});

city.agents.add(agent);
```

CLI and Desktop may keep `config.toml` as the Profile source of truth, but Agent stores neither
Plugin instances nor binding relationships. A Plugin registers Config actions during `start()`, and City injects
the selected Profile's `get/set` store when invoking one. Runtime Actions, Hooks, and lifecycle
`connect` read `context.config` projected for the current Agent.

Do not store live connections, callbacks, or clients in a Profile. City-level resources belong to
`start/stop`; Agent/Workspace resources belong to `connect/disconnect`.
