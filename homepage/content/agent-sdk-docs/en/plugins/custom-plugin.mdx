# Custom Plugin

Custom Plugin contracts come from `@downcity/plugin`. Agent does not accept Plugin instances or
expose a Plugin Registry. City registers a module first, then binds an Agent by `plugin_id`/Profile.

```ts
import {
  BasePlugin,
  define_city_plugin,
  type PluginActions,
} from "@downcity/plugin";

class NotesPlugin extends BasePlugin {
  readonly name = "notes";
  readonly title = "Notes Helper";
  readonly description = "Adds note-related actions.";

  readonly actions: PluginActions = {
    status: {
      execute: async ({ context }) => ({
        success: true,
        data: {
          workspace_path: context.workspace.path,
          storage_path: context.storage.path,
          session_id: context.session?.id ?? null,
        },
      }),
    },
  };
}

const notes_module = define_city_plugin({
  activate() {},
  create: () => new NotesPlugin(),
});

const registration = {
  id: "notes",
  title: "Notes Helper",
  description: "Adds note-related actions.",
  readme: "/absolute/path/README.md",
  has_config: false,
  has_sidebar: false,
  has_mainview: false,
  module: notes_module,
};

const city = new City({ plugins: [registration], workspaces: [workspace] });
city.agents.add(agent, { plugins: [{ plugin_id: "notes" }] });
```

Implement only the Actions, Hooks, Resolves, System, Availability, HTTP, or Lifecycle behavior the
domain actually needs. Use `start/stop` for shared Profile resources and `bind/unbind` for
Agent/Workspace resources. Do not hide long-lived resources inside Hooks.

See [Plugin Development](/en/agent-sdk-docs/plugins/plugin-development) for the complete module,
manifest, Context, and testing model.
