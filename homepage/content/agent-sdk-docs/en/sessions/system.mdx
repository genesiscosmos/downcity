# `session.system()`

## Example

```ts
const system = await session.system();
```

## What It Returns

It returns a structured system snapshot:

```ts
{
  session_id: string;
  session: {
    agent_id: string;
    session_id: string;
    project_root: string;
    created_at: string;
    timezone: string;
  };
  blocks: Array<{
    source: "core" | "instruction" | "power" | "session";
    name: string;
    content: string;
  }>;
}
```

The blocks can include:

- the Agent identity block, carrying the Agent `name` and `id`
- caller-provided static `instruction`
- Downcity Agent core guidance, including Harness design, Shell command rules, and power system rules
- registered and enabled power system text
- stable session context, including `session_id`, `project_root`, creation time, and timezone

The returned blocks are the same stable system blocks used by `session.prompt()`. The first generated system is fixed in the Session's memory; later Agent instruction or plugin registry changes do not alter it. Newly created Sessions use the latest configuration.

To explicitly adopt the Agent's current configuration in an existing local Session, call [`session.syncshot()`](/en/agent-sdk-docs/sessions/syncshot).

The session creation time and timezone are the reference time context for the conversation. Dynamic values such as current time should be placed in the user message, not in `instruction`.

## Block Order

`@downcity/agent` builds system blocks in a fixed order:

1. `instruction` / `identity`: the Agent `name` and `id`, injected by the SDK. The Agent identity is stable across every Session of that Agent.
2. `instruction` / `agent`: the host-provided Agent role, business rules, and response preferences.
3. `core`: fixed Downcity Agent runtime guidance, including Harness design, Shell command rules, and power system rules.
4. `power`: each enabled, ready, and currently available power's own system prompt.
5. `session`: stable context for the current session.

Even when the host provides `instruction`, `core` is still injected immediately after it. The `session` block describes the session itself and does not repeat the Agent identity.

```json
  ]

```

## What It Does Not Do

`session.system()` does not write system prompts into canonical Message history.

Session history stays focused on visible user and assistant messages. Use `system()` when you need to inspect the prompt context that will be sent alongside that history.
