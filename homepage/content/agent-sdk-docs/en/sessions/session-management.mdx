---
title: Managing Sessions
description: Create, open, list, archive, and permanently clean up Sessions
---
`agent.sessions` is the local collection entry point. A session may choose a Workspace as its initial directory, and may switch it later.

## Create and open

```ts
const created = await agent.sessions.create({
  workspace,
});

const task_session = await agent.sessions.create({
  workspace,
  origin: { type: "task", task_id: "daily-report" },
});

const existing = await agent.sessions.get("session-id-from-list", "work");
const existing_task = await agent.sessions.get(task_session.id, "task");
```

`create()` always generates the Session ID internally. To reopen an existing Session, obtain its ID from
`list()` or another persisted reference and pass it to `get(session_id, origin_type = "work")`.
`origin.type` may be any non-empty string and may carry additional JSON metadata. `get()` reads only the
requested partition and never scans other origins.

A Workspace is the session's current directory, not its identity. It is a persisted configuration field
on the session, sharing the `set()` handle with `model`:

```ts
const session = await agent.sessions.create({ workspace: repo_a });

await session.set({ workspace: repo_b });   // move to another repo with history intact
await session.set({ workspace: null });     // leave the project context
```

Only `workspace_id` is written to disk; the instance stays with the host and comes back through
`AgentOptions.resolve_workspace`. Passing a Workspace to `get()` different from the persisted one is
also not an error; it becomes the new current directory:

```ts
const reopened = await agent.sessions.get(session.id, "work", { workspace: repo_c });
```

Switching does not migrate existing messages, attachments, or tool results; those belong to the
directory they happened in. A running turn keeps the previous directory, and the change applies from
the next step checkpoint. A session without a Workspace is valid: it has no file tools and no shell,
while plain model conversation still works.

## The agent's own session

The agent itself is a session, obtained with `agent.session()`; its `session_id` equals the agent's `id`
and its role is `origin.type = "agent"`. It does not appear in the default `work` partition list.
See [Agent session](/en/agent-sdk-docs/sessions/agent-chat).

## List and search

```ts
const page = await agent.sessions.list({
  origin_type: "work",
  limit: 30,
  query: "repo",
});

for (const item of page.items) {
  render_session_row(item);
}

if (page.has_more) {
  const next_page = await agent.sessions.list({
    limit: 30,
    cursor: page.next_cursor,
    query: "repo",
    origin_type: "work",
  });
}
```

`list()` defaults to the `chat` partition. Pass `origin_type` to list another partition. List items are lightweight summaries, not complete Messages. Common fields are `session_id`, `origin`, `title`, `preview_text`, `message_count`, `model_label`, `updated_at`, and `executing`. `cursor` is opaque: return it to the SDK unchanged.

`query` is a lightweight contains filter for a session picker. It is not a full-text search language.

## Archive and clean up

```ts
await agent.sessions.archive({ id: "repo-analysis", origin_type: "task" });

const archived_page = await agent.sessions.archived({ origin_type: "task", limit: 30 });

const removed = await agent.sessions.clean_archive();
console.log(removed.removed_session_ids);
```

Archiving removes a Session from the active list without immediately destroying it. A running Session cannot be archived; wait for its Turn or call `stop()` first.

`clean_archive()` permanently deletes every archived Session. Treat it as an explicit empty-trash action and require user confirmation in a UI.

For local maintenance, `remove(session_id, origin_type = "work")` permanently deletes one active Session's Agent-owned data. `clear_messages(session_id, origin_type = "work")` clears only its messages. Power-owned data is not deleted implicitly; call the owning Power when a workflow also needs to remove domain data.

## UI guidance

1. Use lightweight `list()` summaries for the sidebar.
2. After selection, call `get()` and then load `messages()`.
3. Render `executing: true` as the runtime state; do not guess from timestamps.
4. Remove an archived item from the active list and reload archived data after success.

A Session title can be empty. The presentation layer should fall back to `session_id` or a product-defined placeholder.
