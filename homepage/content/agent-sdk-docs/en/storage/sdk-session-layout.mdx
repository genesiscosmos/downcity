# SDK Session Layout

Local SDK Agent Sessions are persisted under the City-provided storage root; with a local provider this
is commonly `~/.downcity`:

```text
~/.downcity/agents/<agent_id>/sessions/<origin_type>/<session_id>/
├── meta.json
└── messages/
    ├── active.jsonl
    ├── assistant_message.json
    └── segments/
        └── <start_sequence>-<end_sequence>.jsonl
```

The stable identity is `(origin.type, session_id)`. `chat` is the default partition. Other non-empty origin
types are safely encoded into one path segment, so values such as `automation/daily` cannot create nested
directories. `meta.json` v2 records the owning `agent_id` and complete immutable `origin`, and adds
`workspace_id` only when a Workspace was passed to the Session. The project directory never receives a `.downcity` directory.

- `active.jsonl`: complete `SessionMessage` snapshots retained after the latest Compact.
- `assistant_message.json`: the one complete in-progress Assistant draft.
- `segments/*.jsonl`: immutable history ranges with real Messages first and a cumulative Summary footer last.
- `meta.json`: a lightweight index of Agent, origin, and Workspace ownership, title, model label, timestamps, message count, and storage bytes; it never stores the runtime model instance.

Segment filenames use zero-padded 12-digit sequences, such as `000000000001-000000000900.jsonl`. There is no manifest; scanning filenames determines history order. A Summary is not a Message and consumes no sequence.

Applications should call `session.messages()` for Active and use `before_sequence` to load older Segments. Do not write these files directly.

See [Session metadata and storage](/en/agent-sdk-docs/sessions/metadata-and-storage) for progression, Compact, and recovery behavior.
