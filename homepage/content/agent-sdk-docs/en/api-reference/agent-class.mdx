# Agent Class

`Agent` is the reusable subject of the local SDK. It owns identity, instruction, model, custom
Tools, Plugin registration, and the set of Workspaces it has entered. It does not own a permanent
Workspace or a global Session collection.

## Public API

- `new Agent(options)`
- `agent.enter(workspace)`
- `agent.workspaces()`
- `agent.workspace(workspace_id)`
- `agent.set_instruction(input)`
- `agent.get_instructions()`
- `agent.get_logger()`
- `agent.plugins`
- `agent.dispose()`

`agent.enter(workspace)` returns an `AgentWorkspace`. Local Sessions belong to that execution
scope:

```ts
const agent_workspace = agent.enter(workspace);
const session = await agent_workspace.sessions.create();
```

## Constructor options

- `id`: stable Agent identity and private data partition key.
- `tools`: custom Tools shared by every AgentWorkspace.
- `instruction`: static Agent-level base instruction.
- `model`: default `AgentModel`; a local Session may override it.
- `plugins`: Plugin objects registered once on the Agent.
- `session_class`: optional custom local Session class.

There is no `workspace` constructor option. The host creates Workspace independently and enters it
when that Agent needs to work in the project.

## AgentWorkspace

`AgentWorkspace` exposes `workspace`, `sessions`, `tools`, `plugins`, `data_path`, and `leave()`.
Its Session collection provides `create`, `get`, `list`, `archive`, `archived`, `clean_archive`,
`remove`, and `clear_messages`.

One Agent may enter multiple Workspaces. `agent.dispose()` leaves every active AgentWorkspace,
closes its Shell and storage resources, and then unregisters Agent-level Plugins. Network transports
created by `@downcity/city` remain owned by the host.
