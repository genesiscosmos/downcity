# SDK Surface

The SDK is session-first. `Agent` owns local runtime assembly and `RemoteAgent` connects to an exposed runtime.

## `Agent`

- `new Agent(options)`, `ready()`, `dispose()`
- `sessions.create()`, `get()`, `list()`, `archive()`, `archived()`, `clean_archive()`, `remove()`, `clear_messages()`
- `set_instruction()`; Workspace exposes `get_env()`, `set_env()`, and `patch_env()`
- `get_logger()`, `get_shell()`, and `plugins`

Local plugin actions use `agent.plugins.run_action(...)`. HTTP and RPC transports are supplied by `AgentHTTP` and `AgentRPC` in `@downcity/server`.

Agent owns its runtime state and long-lived objects, while Workspace owns project env and resources. The full project config remains in an upstream host such as the CLI. `PluginContext` is an internal projection for plugins; hosts use the explicit Agent facade.

`agent.get_logger()` returns the logger owned by that Agent. For standalone integration code, `get_logger(project_root?)` creates a new independent logger instance; the package does not expose a process-global logger.

## `RemoteAgent`

- `new RemoteAgent({ url, token? })`
- `sessions` collection methods matching local Agent
- `run_plugin_action()` and `close()`

HTTP URLs use the server root such as `http://127.0.0.1:5314`; RPC uses `rpc://127.0.0.1:15314`.

## Sessions

Both local and remote Sessions provide `get_info()`, `prompt()`, `stop()`, `subscribe()`, `messages()`, `system()`, `approvals()`, `approval_mode()`, `set_approval_mode()`, `resolve_approval()`, and `fork()`.

Local Sessions additionally provide `set({ model })` with a runtime model instance, `syncshot()` for explicitly regenerating the system, and `snapshot()` for persisting the fixed complete system. Remote Sessions expose none of these capabilities; the server host owns their model and system persistence policy.

`subscribe()` emits the unified live Mutation stream after the subscription is established. Load initial Message and Session snapshots, and reload them after reconnecting.
