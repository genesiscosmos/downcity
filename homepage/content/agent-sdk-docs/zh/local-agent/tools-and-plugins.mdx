# Tools 和 Plugins

Tool 与 Plugin 都能参与 Session 执行，但所有权不同：Agent 持有自定义 Tool；City 持有 Plugin
唯一实例、配置投影与生命周期。

## 自定义 Tools

本地 Agent 直接接收自定义 Tool：

```ts
const agent = new Agent({
  id: "repo-helper",
  tools: {
    my_tool,
  },
});
```

这些 Tool 会与当前 Session 所选 Workspace 的 Tool 合并。名称冲突会直接报错，不会静默覆盖。

## Workspace 与 Shell

Workspace 默认提供 `grep`、`find`、`read`、`write` 和 `edit`。需要命令执行时显式配置 Shell：

```ts
import { Agent } from "@downcity/agent";
import { MicrosandboxProvider } from "@downcity/sandbox-microsandbox";
import { Shell, Workspace } from "@downcity/city";

const agent = new Agent({ id: "repo-helper" });
const workspace = new Workspace({
  id: "project",
  path: "/path/to/project",
  shell: new Shell({
    sandbox_provider: new MicrosandboxProvider(),
  }),
  runtime_path: "/path/to/downcity-runtime/project",
});
```

Shell 额外提供 `shell_exec` 与 `shell_session`。文件和搜索 Tool 始终受 Workspace 根目录约束；审批与异步问题归属于具体 Session，通过 `session.interactions()` 和 `session.respond(...)` 处理。

## City 提供 Plugins

Agent 构造函数不接收 Plugin。把 registration 交给 City 后，所有 Agent 会自动获得它：

```ts
import { Agent } from "@downcity/agent";
import { City } from "@downcity/city";
import { create_builtin_plugin_registrations } from "@downcity/plugins";
import { Workspace } from "@downcity/city";

const workspace = new Workspace({
  id: "project",
  path: "/path/to/project",
});
const agent = new Agent({ id: "repo-helper", model });
const city = new City({
  workspaces: [workspace],
  plugins: create_builtin_plugin_registrations(),
});

city.agents.add(agent);
```

City 会把全部已注册 Plugin 自动提供给全部 Agent。运行中的 City 可通过
`city.plugins.add()` 与 `city.plugins.remove()` 动态修改 Plugin 集合。

一个 City 中每个 Plugin ID 只有一个实例，并且只有 City 级 `initialize/dispose` 生命周期。
Agent 与 Workspace 只提供每次调用的上下文，不拥有 Plugin 生命周期。

## City 级配置

需要配置的 Plugin 由宿主提供唯一 Config store。配置不进入 Agent，也不决定 Plugin 实例数量：

```ts
const city = new City({
  plugin_host: {
    config: (plugin_id) => open_plugin_config_store(plugin_id),
  },
});
```

每个 Plugin ID 在一个 City 中只有一份配置。多账号结构和选择规则由 Plugin 自己表达，City
不提供通用命名配置层。配置保存后，Plugin 负责刷新受影响的长期资源。

## 调用 Plugin

宿主从 Agent/Workspace 执行入口调用 Action 或 Hook：

```ts

const result = await city.plugins.scope({ agent_id: agent.id, workspace_id: workspace.id }).run_action({
  plugin: "memory",
  action: "search",
  payload: { query: "项目约定" },
});

const enriched = await city.plugins.scope({ agent_id: agent.id, workspace_id: workspace.id }).pipeline("chat.enrich_message", input);
await city.plugins.scope({ agent_id: agent.id, workspace_id: workspace.id }).guard("review.require_checked", enriched);
```

存在 Action 时，Session 会获得 `plugin_read` 和 `plugin_call` Tool。模型先读取 Action schema，再执行经过校验的 payload。Plugin 的 `system(context, execution_context)` 也会在 Session prompt 检查点注入。

## PluginContext 直接通信

Plugin 作者 API 从 `@downcity/city/plugin` 导入。Action、Hook、System 和 Availability 获得 `PluginContext`，其中包含受限的 `city`、`agent`、`workspace`、`session`、`turn`、`config` 和 `storage` 句柄。

`context.session` 与 `context.agent.sessions` 都是可直接调用的进程内对象，不需要只保存 `session_id` 再回查宿主。Workspace 文件使用 `context.workspace.files`；Plugin 私有文件使用 `context.storage.files`。

## HTTP

Plugin 可声明结构化 HTTP route。City 统一挂载、鉴权并注入请求对应的 PluginContext；Plugin 不创建独立服务器。
