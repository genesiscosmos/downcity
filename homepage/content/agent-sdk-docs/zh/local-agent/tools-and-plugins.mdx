# Tools 和 Plugins

Tool 与 Plugin 都能参与 Session 执行，但所有权不同：Agent 持有自定义 Tool；City 持有 Plugin catalog、Profile 共享实例与生命周期。

## 自定义 Tools

本地 Agent 直接接收自定义 Tool：

```ts
const agent = new Agent({
  id: "repo-helper",
  tools: {
    my_tool,
  },
});
```

这些 Tool 会与当前 Session 所选 Workspace 的 Tool 合并。名称冲突会直接报错，不会静默覆盖。

## Workspace 与 Shell

Workspace 默认提供 `grep`、`find`、`read`、`write` 和 `edit`。需要命令执行时显式配置 Shell：

```ts
import { Agent } from "@downcity/agent";
import { MacOsSeatbeltSandbox } from "@downcity/sandbox-macos";
import { Shell, Workspace } from "@downcity/workspace";

const agent = new Agent({ id: "repo-helper" });
const workspace = new Workspace({
  id: "project",
  path: "/path/to/project",
  shell: new Shell({ sandbox: new MacOsSeatbeltSandbox() }),
});
```

Shell 额外提供 `shell_exec` 与 `shell_session`。文件和搜索 Tool 始终受 Workspace 根目录约束；审批与异步问题归属于具体 Session，通过 `session.interactions()` 和 `session.respond(...)` 处理。

## City 提供 Plugins

Agent 构造函数不接收 Plugin。先把 registration 交给 City，再为 Agent 声明所需 Plugin ID：

```ts
import { Agent, City } from "@downcity/agent";
import { create_builtin_plugin_registrations } from "@downcity/plugins";
import { Workspace } from "@downcity/workspace";

const workspace = new Workspace({
  id: "project",
  path: "/path/to/project",
});
const agent = new Agent({ id: "repo-helper", model });
const city = new City({
  workspaces: [workspace],
  plugins: create_builtin_plugin_registrations(),
});

city.agents.add(agent, {
  plugins: [
    { plugin_id: "skill" },
    { plugin_id: "memory" },
  ],
});
```

City 不会自动给每个 Agent 启用全部 Plugin。`CityOptions.plugins` 或 `city.plugins.provide()` 只登记 catalog；`city.agents.add()` 或 `city.plugins.register()` 才建立 Agent/Profile 绑定。

相同 `(plugin_id, profile_id)` 在一个 City 内共享一个实例。`start/stop` 管理这个共享实例，`bind/unbind` 管理 Agent/Workspace scope。

## Profile 配置

需要配置的 Plugin 在绑定中传入 Profile。比如 Web、Image、Chat 的 provider、凭据或 Owner 路由都属于 Profile，不进入 Agent：

```ts
await city.plugins.register(agent.id, {
  plugin_id: "web",
  profile: {
    id: "primary",
    config: {
      browser: "playwright",
      cdp_url: "http://127.0.0.1:9222",
    },
  },
});
```

## 调用 Plugin

宿主从 Agent/Workspace 执行入口调用 Action 或 Hook：

```ts
const entry = await city.enter_workspace(agent.id, workspace.id);

const result = await entry.plugins.run_action({
  plugin: "memory",
  action: "search",
  payload: { query: "项目约定" },
});

const enriched = await entry.plugins.pipeline("chat.enrich_message", input);
await entry.plugins.guard("review.require_checked", enriched);
```

存在 Action 时，Session 会获得 `plugin_read` 和 `plugin_call` Tool。模型先读取 Action schema，再执行经过校验的 payload。Plugin 的 `system(context, execution_context)` 也会在 Session prompt 检查点注入。

## PluginContext 直接通信

Plugin 作者 API 从 `@downcity/plugin` 导入。Action、Hook、System 和 Availability 获得 `PluginContext`，其中包含受限的 `city`、`agent`、`workspace`、`session`、`turn`、`profile` 和 `storage` 句柄。

`context.session` 与 `context.agent.sessions` 都是可直接调用的进程内对象，不需要只保存 `session_id` 再回查宿主。Workspace 文件使用 `context.workspace.files`；Plugin 私有文件使用 `context.storage.files`。

## HTTP

Plugin 可声明结构化 HTTP route。City 统一挂载、鉴权并注入请求对应的 PluginContext；Plugin 不创建独立服务器。
