# Plugin 配置

Plugin 模块由 City 登记，Profile 由宿主配置，Agent 只引用 Plugin ID/Profile ID：

```text
Plugin catalog registration
→ 宿主读取并校验 Profile 配置
→ City 创建唯一 (plugin_id, profile_id) 实例
→ Agent 建立 plugin_id/profile 绑定
→ Session 取得当前 Workspace 的执行视图
```

SDK 可以在 City 构造时登记：

```ts
const city = new City({
  plugins: [registration],
  workspaces: [workspace],
});

city.agents.add(agent, {
  plugins: [{
    plugin_id: registration.id,
    profile: { id: "team", config: { endpoint: "https://example.com" } },
  }],
});
```

也可以动态登记和绑定：

```ts
city.plugins.provide(registration);
await city.plugins.register(agent.id, {
  plugin_id: registration.id,
  profile,
});
```

CLI/Desktop 的 `config.toml` 是 Profile 配置事实源，`agent.json` 只保存引用，不保存渠道、账号、
端点或 Token。Config action 由 Plugin main 注册，City 在调用时注入当前 Profile 的 `get/set` store。

相同 `(plugin_id, profile_id)` 的配置在一个 City 中必须一致；它对应一个共享实例与一组长期资源。
不提供 Config 的 Plugin 使用 `default` Profile。运行态连接、回调和客户端对象不能写入 Profile。

Chat Profile 额外要求唯一路由：跨 Agent/Workspace 复用时必须显式配置 `owner_agent_id` 与
`owner_workspace_id`。
