# Plugin 配置

一个 City 中，每个 Plugin ID 只有一份宿主配置：

```text
宿主保存 Plugin Config
→ City 持有一个 Plugin 实例
→ City 在每次执行时投影配置快照
→ Plugin 从当前 PluginContext.config 读取
```

```ts
const city = new City({
  plugins: [web_plugin],
  workspaces: [workspace],
  plugin_host: {
    config: (plugin_id) => open_plugin_config_store(plugin_id),
    notifications: (plugin_id, agent_id) => open_notifications(plugin_id, agent_id),
  },
});

city.agents.add(agent);
```

`PluginConfigStore.get()` 同步返回当前完整配置快照，`set(config)` 原子替换完整配置。Agent
不保存 Plugin 引用或配置；同一份配置会提供给所有 Agent。多账号或多租户结构由具体 Plugin
在自己的 Config 中定义，City 不提供通用命名配置层。

Config action 由 Plugin 在 `initialize()` 中注册。City 调用 `city.plugins.invoke_config()` 时注入
该 Plugin 唯一的 `get/set` store；Action、Hook、System 与 Availability 则从当前调用的
`PluginContext.config` 读取不可变快照。

配置保存后，Plugin 应主动释放或刷新受配置影响的长期资源。连接、回调和客户端对象不能写入
Config；它们仍由 Plugin 按账号、Agent 或其他真实领域身份管理，并最终由 `dispose()` 统一释放。
