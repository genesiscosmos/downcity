# Plugin 配置

配置不决定 Plugin 所有权或实例数量：

```text
宿主保存 Plugin Profile
→ City 持有一个 Plugin 实例
→ plugin_host.runtime_config(plugin_id, agent_id) 投影配置
→ Plugin 从当前 PluginContext.config 读取
```

```ts
const city = new City({
  plugins: [web_plugin],
  workspaces: [workspace],
  plugin_host: {
    runtime_config: (plugin_id, agent_id) => load_runtime_config(plugin_id, agent_id),
    profile_config: (plugin_id, profile_id) => open_profile_store(plugin_id, profile_id),
    notifications: (plugin_id, agent_id) => open_notifications(plugin_id, agent_id),
  },
});

city.agents.add(agent);
```

CLI/Desktop 的 `config.toml` 可以继续作为 Profile 配置事实源，但 Agent 不保存 Plugin 实例或
绑定关系。Config action 由 Plugin 在 `initialize()` 中注册，City 调用时注入指定 Profile 的 `get/set` store；
执行期 Action、Hook、System 与 Availability 读取当前 Agent 投影得到的 `context.config`。

运行态连接、回调和客户端对象不能写入 Profile。长期资源属于 Plugin，并应按实际账号、Profile
或其他领域身份建立索引，最终由 `dispose` 统一释放。
