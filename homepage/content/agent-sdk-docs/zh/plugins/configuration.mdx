# Plugin 配置

Agent SDK 只负责运行已经构造好的 Plugin 实例，不读取 City 的安装目录或 Profile：

```ts
await agent.plugins.register(new SkillPlugin());
await agent.plugins.unregister("skill");
```

## SDK 宿主

嵌入式宿主通过 Plugin constructor 直接传入运行配置。constructor 的形状完全由 Plugin 作者决定：

```ts
import { ChatPlugin, TelegramChannel } from "@downcity/plugins/chat";

const chat_plugin = new ChatPlugin({
  queue: { max_concurrency: 4 },
  channels: [
    new TelegramChannel({
      id: "telegram_main",
      name: "Main Bot",
      bot_token: process.env.TELEGRAM_BOT_TOKEN ?? "",
    }),
  ],
});

await agent.plugins.register(chat_plugin);
```

SDK 宿主自己拥有凭据来源、配置界面和实例装配，不需要创建 Profile。

## CLI / Desktop 宿主

通用宿主不能猜测任意 Plugin constructor，因此使用 Plugin 包的可选 `agent` factory：

```text
Plugin Catalog
→ 用户在对应 Plugin 详情页的 Config 中管理 Profile
→ Agent 对有 Config 的 Plugin 保存 plugin_id → profile_id 引用
→ 宿主读取 Profile 快照并调用 agent factory
→ Agent Runtime Plugin
```

Profile 只是声明 Config 的 Plugin 下的命名配置空间，与 Sidebar/Mainview 功能工作区无关。宿主统一负责创建、选择、删除和持久化；Plugin 自己的 Config actions 负责内容校验与安全投影，`config` 插槽负责编辑体验。没有 Config 的 Plugin 不需要 Profile，Agent 只保存启用状态。宿主不使用 JSON Schema 生成通用表单，也不把渠道、账号或 Token 写进 `agent.json`。

## 推荐理解方式

- Agent SDK：接收并运行 Plugin 对象。
- SDK 宿主：直接构造 Plugin，并拥有自己的配置来源。
- CLI / Desktop：拥有 Catalog、安装、Profile 与 Agent 引用。
- Plugin：拥有业务配置结构、Config actions 和 Config UI。
