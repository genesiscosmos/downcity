# Plugin Actions

Action 是 Plugin 的显式业务入口，由 `description`、可选输入 schema/command/api、超时和
`execute` 组成。

```ts
import { create_action } from "@downcity/city/plugin";
import { z } from "zod";

const status = create_action({
  description: "Read the current execution scope.",
  input_schema: { zod: z.object({}) },
  timeout_ms: 30_000,
  execute: async ({ context, execution }) => ({
    success: true,
    data: {
      agent_id: context.agent.id,
      workspace_id: context.workspace.id,
      session_id: context.session?.id ?? null,
      turn_id: context.turn?.id ?? null,
      call_id: execution.call_id,
    },
  }),
});
```

每次调用有两个只读输入：

- `context` 是 City 创建的作用域能力，包含受限 City、Agent、Workspace、Session、Turn、Profile 与 Storage 对象。
- `execution` 是单次 Action 身份，包含 `call_id`、`abort_signal`、可选 Session scope 与 Step snapshot。

Action 应把 `execution.abort_signal` 传给网络请求、轮询和长耗时任务。`timeout_ms` 只触发协作式
取消，底层操作必须响应信号。返回值必须是可 JSON 序列化的 `PluginActionResult`。

`command` 只把 Commander 输入映射为 payload；`api` 只把 HTTP 请求映射为 payload。它们不创建
第二套业务入口，最终都执行同一个 `execute`。

模型通过当前 Session 的 `plugin_call` Tool 调用 Action。Plugin 内部可以通过
`context.city.plugins.run_action()` 调用当前 Agent 已绑定的其他 Plugin；应用代码则从
`city.enter_workspace()` 返回的执行入口调用 `entry.plugins.run_action()`。
