# Plugin Availability

Plugin 当前只需要区分两件事：

- 是否已经由 City 绑定到当前 Agent，并投影到 `entry.plugins`
- 当前环境是否满足 plugin 自己的 `availability()` 检查

绑定是执行可见性边界。只登记在 City catalog、但没有绑定到当前 Agent 的 Plugin，不会出现在该 Agent 的执行入口中。

## 绑定状态

```ts
entry.plugins.has("skill");
entry.plugins.status("skill");
entry.plugins.snapshots();
```

Plugin 刚绑定且共享实例的 lifecycle 尚未完成时，状态是 `initializing`。Action、Availability、System 和 Hook 会等待初始化完成，不会在 `start` 前执行。

如果 Plugin 已绑定且启动成功，状态是 `ready`。

如果 lifecycle 启动失败，状态可能是 `error`，用于诊断。普通 action 业务失败不会把整个 plugin 标成 `error`；例如 `skill.lookup` 查不到某个 skill 时，只返回这次 action 的失败结果，plugin 仍保持可继续调用。

## `availability()`

`availability()` 不再表达开关。

它只回答：

> 在当前 Agent 上下文里，这个 plugin 现在能不能真正工作？

例如：

- provider 还没安装
- Python 依赖没准备好
- 模型没下载好
- API key 没配置

```ts
const availability = await entry.plugins.availability("skill");
```

返回结果仍然包含 `enabled` 字段，但它表示“Plugin 是否绑定到当前 Agent”，不是项目配置开关。

## 最稳的理解

把它记成两句：

- City 的 Agent 绑定 / 解绑决定 Plugin 是否在执行作用域中可见
- `availability()` 决定已绑定 Plugin 在当前作用域是否可用
