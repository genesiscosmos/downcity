# Plugin 总览

Plugin 是 Downcity 的统一扩展产品单元，可以提供 Action、Hook、Resolve、System、Availability、
HTTP Route、生命周期以及可选的 Mainview/Config。

Plugin 不属于 Agent。City 持有 catalog、main、`(plugin_id, profile_id)` 共享实例与完整生命周期；
Agent 只保存“使用哪个 Plugin/Profile”的绑定；Session 在执行检查点取得只读 Plugin 视图。

## SDK 装配

```ts
import { Agent, City } from "@downcity/agent";
import { create_builtin_plugin_registrations } from "@downcity/plugins";

const registrations = create_builtin_plugin_registrations();
const city = new City({ workspaces: [workspace], plugins: registrations });
const agent = new Agent({ id: "repo-helper", model });

city.agents.add(agent, {
  plugins: [
    { plugin_id: "skill" },
    { plugin_id: "memory" },
  ],
});
```

SDK 不会自动启用所有内建 Plugin。`CityOptions.plugins` 或 `city.plugins.provide()` 负责登记；
`city.agents.add()` 与 `city.plugins.register()` 负责 Agent/Profile 绑定。

## PluginContext

Action、Hook、System 与 Availability 都使用当前作用域的 `PluginContext`。它提供受限的：

- `city`：Embassy 与 Plugin 间协作端口。
- `agent`：身份、指令和 Session 集合。
- `workspace`：文件、Shell、env 与稳定 ID。
- `session` / `turn`：当前调用存在 Session/Turn 时的直接通信句柄。
- `profile`：当前共享实例的 Profile 快照。
- `storage`：当前 Agent/Plugin 私有存储。

对象句柄用于进程内直接通信，ID 用于稳定身份和序列化；Plugin 不需要只拿 `session_id` 再绕回宿主查询。

## Profile 与共享实例

相同 `(plugin_id, profile_id)` 在一个 City 中只有一个实例。`start/stop` 属于该共享实例，
`bind/unbind` 属于 Agent/Workspace scope。Memory 因此可以由一个 City 实例服务多个 Agent，并在
逻辑地址中区分 City、Agent、User 和 Workspace 作用域。

同一个 Chat Profile 只允许一组渠道连接和队列；跨 scope 复用时必须配置
`owner_agent_id` 和 `owner_workspace_id`。
