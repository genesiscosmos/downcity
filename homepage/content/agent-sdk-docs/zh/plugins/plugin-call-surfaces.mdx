# Plugin 调用入口

Plugin 有四类调用面，分别服务不同角色：

| 入口 | 使用者 | 用途 |
| --- | --- | --- |
| `city.plugins` | 宿主应用 | 登记模块、管理 Agent/Profile 绑定、调用 main/config action |
| `entry.plugins` | 宿主执行代码 | 在指定 Agent/Workspace 上调用 Action、Availability 或 Hook |
| `context.city.plugins` | Plugin 代码 | 在当前作用域调用其他 Plugin Action、pipeline 或 effect |
| `plugin_call` | Session 中的模型 | 调用当前 Agent 已绑定的 Plugin Action |

## City 绑定面

```ts
city.plugins.provide(registration);
await city.plugins.register(agent.id, { plugin_id: "skill" });
console.log(city.plugins.snapshots(agent.id));
await city.plugins.unregister(agent.id, "skill");
```

`city.plugins.invoke()` 与 `invoke_config()` 调用 Plugin main 注册的宿主管理 Action，不是 Session
执行 Action。

## Workspace 执行面

```ts
const entry = await city.enter_workspace(agent.id, workspace.id);
const result = await entry.plugins.run_action({
  plugin: "skill",
  action: "lookup",
  payload: { name: "frontend-design" },
});
```

这个入口显式绑定 Agent 与 Workspace，因此 City 能创建正确的 `PluginContext`。

## PluginContext

```ts
const result = await context.city.plugins.run_action({
  plugin: "skill",
  action: "list",
  payload: {},
});
await context.city.plugins.effect("audit.observe", result.data ?? null);
```

`context.session`、`context.agent.sessions` 和 `context.workspace` 是直接可调用句柄；ID 只用于稳定
身份和序列化。

## 模型 Tool

```ts
plugin_call({
  plugin: "skill",
  action: "lookup",
  payload: { name: "frontend-design" },
});
```

Tool 永远绑定当前 Session 的 Agent/Workspace execution lease，不会读到其他 Agent 的绑定。
