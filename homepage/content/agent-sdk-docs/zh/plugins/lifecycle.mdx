# Plugin Lifecycle

Plugin 由 City 持有，Agent 只声明 `plugin_id` 与可选 Profile 绑定。City 内同一个
`(plugin_id, profile_id)` 只创建一个实例，多 Agent 可以共享它。

## 登记与绑定

```ts
const city = new City({
  workspaces: [workspace],
  plugins: [registration],
});

city.agents.add(agent, {
  plugins: [{ plugin_id: registration.id, profile }],
});
```

也可以动态修改绑定：

```ts
await city.plugins.register(agent.id, {
  plugin_id: registration.id,
  profile,
});
await city.plugins.unregister(agent.id, registration.id);
```

`provide` 只登记模块；`register` 才让某个 Agent 使用一个 Profile。同一 City 中相同 Plugin ID
只能对应同一模块，相同 Profile ID 的配置也必须一致。

## 四个执行生命周期节点

- `start(context)`：首个 Agent 引用该 Plugin/Profile 时执行一次，适合 Profile 共享连接和缓存。
- `bind(context)`：Agent 进入 Workspace 时执行，适合该执行作用域的 scheduler、queue 或路由。
- `unbind(context)`：离开 Workspace、替换 Profile 或解绑 Plugin 时释放对应 scope。
- `stop(context)`：最后一个 Agent 引用和活跃 execution lease 都释放后执行一次。

```ts
readonly lifecycle = {
  start: async ({ profile, storage }) => {
    await this.client.open(profile.config, storage);
  },
  bind: async (context) => {
    await this.scheduler.start(context.agent.id, context.workspace.id);
  },
  unbind: async (context) => {
    await this.scheduler.stop(context.agent.id, context.workspace.id);
  },
  stop: async () => {
    await this.client.close();
  },
};
```

`start/stop` 接收 `PluginLifecycleContext`，其中 storage 属于共享 Profile。`bind/unbind` 接收完整
`PluginContext`，其中 storage 属于当前 Agent/Plugin 执行范围。

## execution lease

Session 在 Step 检查点捕获不可变 Plugin 执行视图。解绑后，新 Step 立即不再看到该 Plugin；已经开始
的 Step 可以继续完成。City 会等待最后一个 lease 释放，再停止共享实例，避免长连接或 Provider 被提前关闭。

`city.close()` 会释放 Workspace scope、Agent 绑定、共享实例和 Plugin main。单个 `stop` 或
`deactivate` 失败不会阻止其他 Plugin 清理，City 会在结束后汇总错误。
