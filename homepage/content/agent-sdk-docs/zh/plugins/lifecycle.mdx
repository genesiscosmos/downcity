# Plugin 生命周期

Plugin 的所有权属于 City。`city.plugins.add(new MyPlugin())` 时登记一个唯一实例；同一 Plugin ID
不能在 City 中重复注册。

## 四个生命周期节点

- `start(context)`：Plugin 加入 City 时执行一次，适合初始化 City 级连接、Provider 与缓存。
- `connect(context)`：Agent 首次进入 Workspace 时执行一次，适合创建 Agent/Workspace 作用域资源。
- `disconnect(context)`：Agent 离开 Workspace 或从 City 移除时执行，释放对应作用域资源。
- `stop(context)`：Plugin 被移除或 City 关闭时执行一次，释放 City 级资源。

```ts
class SchedulerPlugin extends Plugin {
  readonly name = "scheduler";
  async start({ storage }: PluginStartContext) {
    await this.scheduler.open(storage);
  }
  async connect(context: PluginContext) {
    await this.scheduler.connect(context.agent.id, context.workspace.id);
  }
  async disconnect(context: PluginContext) {
    await this.scheduler.disconnect(context.agent.id, context.workspace.id);
  }
  async stop() {
    await this.scheduler.close();
  }
}
```

`start/stop` 使用同一个 `PluginStartContext`；Action、Hook 与 `connect/disconnect` 使用
包含 `agent`、`workspace`、可选 `session/turn` 的 `PluginContext`。City 为每个 Agent/Plugin 分配
私有 Storage，Plugin 实例本身不会按 Agent 复制。

Session 在每个 Step 打开稳定的 Hook 作用域。Plugin 被移除后，新 Step 立即不可见；已经开始的
Step 会在作用域关闭后再释放资源。`city.close()` 会依次关闭 Agent Workspace 作用域、Plugin
实例和 transport，并汇总释放错误。
