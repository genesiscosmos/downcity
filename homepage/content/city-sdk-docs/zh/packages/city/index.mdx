---
title: "City"
description: 持有 Agent、Workspace、Plugin 与 transport 的运行环境。
---

`City` 是 CLI、Desktop 和自定义 Node 宿主共用的组合根。应用创建 Agent；City 持有
Workspace、Plugin 唯一实例、生命周期、Storage、Embassy
以及可选 HTTP/RPC transport。Session 始终由 Agent 的 `AgentSessions` 持有。

```bash
pnpm add @downcity/city @downcity/plugins
```

```ts
import { Agent, City, Workspace } from "@downcity/city";
import { create_builtin_plugin_registrations } from "@downcity/plugins";

const workspace = new Workspace({ id: "project", path: process.cwd() });
const registrations = create_builtin_plugin_registrations();
const city = new City({
  embassy,
  workspaces: [workspace],
  plugins: registrations,
});
const agent = new Agent({ id: "lucas", model });

city.agents.add(agent);

const session = await agent.sessions.create({ workspace });
await (await session.prompt({ query: "总结当前项目" })).finished;
await city.close();
```

## 关系与所有权

- `City` 持有 Plugin catalog、唯一实例、生命周期和 Hook 作用域。
- `Agent` 持有身份、模型、指令、自定义工具和 `AgentSessions`，不持有 Plugin。
- `Session` 归 Agent 所有，在创建时取得一个 Workspace 执行上下文和 City Plugin 执行视图。
- `Workspace` 只持有项目文件、工具、env 与可选 Shell，不拥有 Agent、Session 或 Plugin。

SDK 也可以调用 `city.plugins.add(plugin)` 动态添加实例，或调用 `city.plugins.remove(plugin_id)`
移除。相同 Plugin ID 在一个 City 中只能对应一个实例；全部已注册 Agent 自动共享该实例。

## Workspace 管理

`city.workspaces.add(workspace)` 将 Workspace 交给 City 持有；`get()` 与 `list()` 提供稳定查询。
不再使用某个 Workspace 时，调用 `await city.workspaces.remove(workspace_id)`。City 会先释放该
Workspace 的 Shell、Sandbox 等运行资源，再将其移出当前 City；不存在时返回 `null`。这个操作
只管理运行时对象，不会删除项目目录。

## Plugin 生命周期

一个 Plugin 实例只有一套由 City 管理的生命周期，并在 `initialize` 中注册可选宿主管理 action：

1. Plugin 加入 City 时调用一次 `initialize`。
2. Plugin 移除或 City 关闭时调用一次 `dispose`。

Agent、Session 和 Workspace 的进入或离开都不触发 Plugin 生命周期。长期连接、Timer、调度器和
后台 Worker 由具体 Plugin 按自己的账号、Profile、任务定义等领域所有权管理。

Action、System、Availability 与 Hook 每次调用都会获得即时创建的 `PluginContext`。它包含受限的
`city`、`agent`、`workspace`、`session`、`turn`、`config` 和 `storage` 对象，因此 Plugin
可以直接调用当前 Session 或 Agent 的受限能力，不需要只靠 `session_id` 重新查找。

Hook 仍由 City 唯一的执行 Registry 调度。Session 在明确检查点捕获不可变 Hook 作用域；动态移除后
新 Step 立即看不到 Plugin，已经开始的 Step 可以完成，并在释放作用域后触发最终清理。

CLI daemon 与 Desktop 窗口分别拥有独立的 City 生命周期。宿主协调协议只协调监听权，不修改
Agent、Plugin 或 Session 的持久化数据。
