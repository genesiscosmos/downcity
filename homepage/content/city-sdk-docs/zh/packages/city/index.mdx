`@downcity/city` 同时提供服务端 `Federation` 运行时和产品侧 `City` 客户端。只要你要部署一个能服务多个产品的 Federation，最后都会落到这个包。

这不是“某个 AI SDK 的补充包”，而是整个 server-side Federation 的核心运行时。你注册的 AI service、自定义 service、官方服务，以及统一的 `/v1/*` 调用边界，都会在这里汇合。

建议按下面顺序读：

2. 再读 [Service 与 Action 设计](/zh/city-sdk-docs/packages/city/service-and-action)，理解为什么 AI service、custom service 最后都能走统一路由。

如果你只想先建立总体印象，可以先看完本页，再按顺序读上面四页。

## 这个包真正负责什么

- 创建 `Federation` 服务端实例
- 注册 `Service`、官方服务和 `AIService`
- 管理内置的 city、env 和 token 相关能力
- 暴露统一的 `/v1/*` 路由与调用边界
- 通过 `User City` 和 `FederationAdmin`（均为 `City` 客户端）提供访问入口

## 它不负责什么

- 不负责实现具体数据库 Driver；你创建独立 Database Adapter 后传给 `new Federation({ database })`
- 不负责现成账号、usage、支付业务，这些通过官方服务接入

## 什么时候应该先看它

- 你要搭一个真正可运行的 Federation
- 你要声明自己的 AI service 或自定义 service
- 你要把多产品共用的鉴权、hooks、模型目录放进同一个 Federation 后端

## 最常见的组合关系

| 目标 | 组合方式 |
| --- | --- |
| 本地或常规 Node 部署 | `@downcity/city` + SQLite / PostgreSQL Database Adapter |
| 产品前端或 App 调用 | `@downcity/city` 导出的 `City` 客户端 |
| 账号、usage、支付 | `@downcity/city` + 对应官方服务 |

## 安装

```bash
pnpm add @downcity/city @downcity/database-sqlite
```

## 最小示例

```ts
import { Federation, AIService } from "@downcity/city";
import { Database } from "@downcity/database-sqlite";

const database = new Database({ filename: "./data.sqlite" });
const base = new Federation({ database });

const ai = new AIService();

ai.use({
  id: "local-echo",
  name: "Local Echo",
  default: ["text"],
  actions: {
    text: async (ctx) => ({
      id: crypto.randomUUID(),
      role: "assistant",
      parts: [
        {
          type: "text",
          text: String(ctx.input.prompt ?? ""),
          state: "done",
        },
      ],
    }),
  },
});

base.use(ai);
```

这个示例展示的是 `@downcity/city` 的运行时侧：它负责把数据库和服务挂到同一套 Federation 上。产品侧调用则使用同一个包导出的 City 能力。
