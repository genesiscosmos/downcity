`@downcity/city` 是 CLI、Desktop 和自定义 Node 宿主共用的运行环境容器。它持有
Workspace、Embassy 和可选 HTTP/RPC transport，不创建 Agent、Session 或 Plugin。

```bash
pnpm add @downcity/city @downcity/agent @downcity/workspace
```

```ts
import { Agent } from "@downcity/agent";
import { City } from "@downcity/city";
import { Workspace } from "@downcity/workspace";

const workspace = new Workspace({
  id: "project",
  path: process.cwd(),
});
const city = new City({ embassy, workspaces: [workspace] });
const agent = new Agent({ id: "lucas", model, plugins });
city.agents.add(agent);
const session = await agent.sessions.create({ workspace: city.workspace("project")! });

const current_agent = city.agents.get("lucas");

await city.close();
await agent.dispose();
```

## 所有权

- 应用创建 Agent 和 Plugin，再通过 `city.agents.add(agent)` 将 Agent 纳入 City；每个 Agent 最多绑定一个 City。
- `City` 持有 Workspace、Embassy 和 transport，并只为路由与关闭协调维护 Agent 引用。
- Session 由 Agent 创建，并在创建时显式选择 City Workspace。
- Plugin lifecycle 和 ActionSchedule 归各 Agent 自己拥有。
- CLI daemon 与 Desktop 窗口分别拥有独立的 City 和 Agent 生命周期。

## 宿主协调

CLI 与 Desktop 启动 City 时使用同一份宿主状态。如果另一端已经运行，启动方必须先获得
用户确认，请求已有宿主退出，并等待其释放 transport。这个协议只协调 City 监听权，不给
Agent 增加启动状态，也不修改 Agent、Plugin 或 Session 的持久化数据。

单 Agent 执行、AgentWorkspace、Session、Plugin SDK 和 RemoteAgent 位于
`@downcity/agent`；项目资源与 Shell 位于 `@downcity/workspace`；Federation、Embassy 和
Bureau 位于 `@downcity/federation`。
