`@downcity/agent` 提供单 Agent 执行面，拥有 Agent、AgentSessions、Session、Plugin SDK 和
RemoteAgent。Workspace 资源由 `@downcity/workspace` 提供；本包不拥有多 Agent 宿主或网络 Server。

```ts
const city = new City({ workspaces: [workspace] });
const agent = new Agent({ id: "assistant" });
city.agents.add(agent);
const session = await agent.sessions.create({ workspace });
const turn = await session.prompt({ query: "你好" });
const result = await turn.finished;
```

CLI、Desktop 或 Node 进程需要持有多个 Agent、根据本地配置装配实例或暴露 HTTP/RPC 时，使用
`@downcity/agent`。

## Group 与 GroupSession

`Group` 是具有集体主体性的协作主体，拥有自己的 `model` 和 `GroupSession` 集合。`Group.model` 专门用于理解群聊意图并选择投递成员；默认使用 AI 调度。AI 调度通过一次强制的内部 `dispatch_group` tool call 提交最小投递计划，SDK 再将其编译为内部执行图，不依赖 `generateObject`。未提供模型或模型调用失败时，`GroupSession` 会记录明确的调度失败，不会自动切换到另一套规则；如需自定义行为，应显式提供 `dispatch_strategy`。成员执行仍使用成员 Agent 的 `AgentSession`，不会把私有上下文、Plugin
和工具调用复制进群聊历史。`GroupSession` 的 `prompt()` 只负责立即写入用户消息并启动异步调度；多个调用可以同时进入。GroupSession 只运行一个全局 auto dispatch，在当前成员执行完成后统一判断下一步；消息和 Group/成员运行态统一通过
`subscribe()` 订阅。

`dispatch_group` 的输入只有 `steps` 和 `next`：`steps` 是二维数组，外层阶段按顺序执行，同一阶段数组内的成员并行执行；`next` 为 `continue` 时才允许全局 auto dispatch 继续判断。例如：

```json
{
  "steps": [
    ["architect"],
    ["reviewer"]
  ],
  "next": "stop"
}
```

```ts
const lead = new Agent({ id: "lead", model });
const reviewer = new Agent({ id: "reviewer", model });
city.agents.add(lead);
city.agents.add(reviewer);

const group = new Group({
  id: "delivery-team",
  model,
  members: [lead, reviewer],
});
city.groups.add(group);

const group_session = await group.sessions.create({ workspace });
const result = await group_session.prompt({ query: "请完成实现并让 reviewer 审查改动" });
console.log(result.turn_id, result.success);

const sessions = await group.sessions.list();
const restored = await group.sessions.get(sessions[0].id, { workspace });
```

`Workspace` 仍然是 City 提供的资源。Workspace 只注入具体的 GroupSession，再由 GroupSession 注入成员 AgentSession；它不属于 Agent、
Group，也不决定成员如何协作。加入带持久化 Storage 的 City 后，GroupSession 会保存自己的 Workspace ID、消息摘要、成员 AgentSession ID 映射和调度检查点；
进程中断后只依据已落盘的 Group 消息继续 auto dispatch，不会重复提交已经接受的 Agent Turn；
`sessions.list()` 只读取摘要，`sessions.get(id)` 才恢复完整消息和成员会话引用。
