`@downcity/city` is the runtime container shared by the CLI, Desktop, and custom Node hosts. It
owns Workspaces, Embassy services, and optional HTTP/RPC transports. It never creates Agents,
Sessions, or Plugins.

```bash
pnpm add @downcity/city @downcity/agent @downcity/workspace
```

```ts
import { Agent } from "@downcity/agent";
import { City } from "@downcity/city";
import { Workspace } from "@downcity/workspace";

const workspace = new Workspace({
  id: "project",
  path: process.cwd(),
});
const city = new City({ embassy, workspaces: [workspace] });
const agent = new Agent({ id: "lucas", model, plugins });
city.agents.add(agent);
const session = await agent.sessions.create({ workspace: city.workspace("project")! });

const current_agent = city.agents.get("lucas");

await city.close();
```

## Ownership

- The application creates Agents and Plugins; `city.agents.add(agent)` binds an Agent to one City.
- `City` owns Workspaces and Embassy services, and keeps Agent references only for routing and shutdown coordination.
- Sessions are created by the Agent and select a City Workspace explicitly.
- Each Agent owns its Plugin lifecycle and ActionSchedule.
- The CLI daemon and Desktop window own independent City and Agent lifecycles.

## Host coordination

The CLI and Desktop use one host record when starting City. If the other host is already running,
the new host asks for confirmation, requests a graceful shutdown, and waits for the existing process
to release its transports. This protocol only coordinates City listener ownership. It adds no Agent
started state and never modifies persisted Agent, Plugin, or Session data.

Single-Agent execution, internal AgentWorkspace runtime, Session, Plugin SDK, and RemoteAgent remain in
`@downcity/agent`. Project resources and Shell belong to `@downcity/workspace`. Federation,
Embassy, and Bureau belong to `@downcity/federation`.
