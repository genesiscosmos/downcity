title: "@downcity/city"
description: Assemble and host one or more Agent instances from product configuration.
---

`@downcity/city` is the Agent host package used by the CLI, Desktop, and custom Node hosts.
It owns the Agent collection, local configuration assembly, and optional HTTP/RPC transports.

```bash
pnpm add @downcity/city @downcity/agent
```

```ts
import { City, LocalCityEnvironment, LocalCityStore } from "@downcity/city";

const store = new LocalCityStore();
const environment = new LocalCityEnvironment({ data_source: store });
const city = new City(store, environment);
await city.ready();

const agents = city.agents();
const agent = city.agent("lucas_whitman");

await city.dispose();
```

## Ownership

- `LocalCityStore` only owns its database connection and supplies `CityAgentConfig` values.
- `LocalCityEnvironment` converts product configuration into runtime-only `AgentOptions`.
- `City` calls `new Agent(options)`, owns the resulting instances, and owns HTTP/RPC transports.
- `city.add/remove` only manage runtime instances; they never read or mutate product configuration.
- Each Agent owns its Plugin lifecycle and ActionSchedule.
- The CLI and Desktop create independent City instances but read the same `~/.downcity` data.
- The CLI daemon and Desktop window own independent City lifecycles while reading the same persistent data.

Single-Agent execution, Workspace, Session, Plugin SDK, and RemoteAgent remain in
`@downcity/agent`. Federation, Embassy, and Bureau belong to `@downcity/federation`.
